## 通读项目并输出《面试准备指南》

用户诉求：这个项目是秋招作品集（复刻只狼弦一郎 Boss 战），想知道面试该重点准备哪些问题。

产出：`Docs/面试准备指南.md`（三个梯队 + 最大风险点 + 面试前 5 件事）。

### 项目实况（通读后确认）
- 106 个 .cs / 约 16200 行，Unity 2022 LTS + URP
- 技术栈：HFSM + 命令模式 + 行为树 + SO 数据驱动 + 静态事件总线 + Cinemachine + Input System + DoTween
- 17 个模块（M1–M17），战斗闭环/Boss AI/表现层代码已完成

### 代码里最值钱的三个设计（面试主讲点）
1. `Hitbox.cs`：LateUpdate + `Physics.SyncTransforms()` + SphereCastAll 扫位移段 + OverlapSphereNonAlloc + OverlapCapsuleNonAlloc（柄到尖 shaftRadius）；三个 HashSet 分工（hitTargets / blockedUntilExit / clashedPartners）；拼刀用 `GetInstanceID()` 比较做确定性去重
2. `DeflectState.cs`（688 行）：DeflectEntryMode 三态（Normal/PassiveGuard/PerfectParry）；抖刀惩罚 raiseSpamGuard；反击按「目标命中时刻 − HitStartTime」倒推 counterFireTime，数学上保证贪刀必被罚
3. HFSM 双路由链：Command 与 HitData 对称自顶向下路由；硬约束「禁止判顶层状态类型」，改用 CharacterBody 的 bool 属性（IsAttacking/IsParried/IsGuarding 等）

### 已知技术债（下次可以直接接活重构）
- `CharacterBody.cs` 1492 行 / 60+ 方法，典型 God Class。成因是「禁止判顶层状态类型」把所有跨层查询接口堆到它身上。建议拆：CombatStats / Locomotion / FacingController / WeaponController + CharacterBody 退化为 Façade
- `CombatManager` 单例（持有场景级成对状态：处决双方、投技双方动画完成标志）
- `CombatEventBus` 静态类，20+ 事件，订阅全靠 OnEnable/OnDisable 配对
- `StateMachine.ChangeState` 每次 new 状态对象 → GC；建议池化
- `Blackboard` 用 `Dictionary<string, object>` → float 装箱 + 字符串哈希
- `CameraController` 有 `GameObject.Find("LockOn Camera")` 字符串查找；`BossVoiceDirector` 有 `FindObjectOfType`
- 无命名空间、无自动化测试（CLAUDE.md 明写不做自动化测试）
- Git 提交信息质量差：「修复」「0826」这类
