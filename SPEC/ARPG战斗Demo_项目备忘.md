## 三、核心机制清单

### 3.1 弹刀系统（核心中的核心）

- 轻点右键 → 进入DeflectState，约12帧@60fps（0.2秒）为完美弹刀窗口
- 完美弹刀效果：无伤、敌方架势大幅上升、火花+打铁声、帧冻结0.03-0.05秒、恢复自身5-10%架势
- 按住右键 → 持续格挡，减伤50-70%，自己架势持续上升
- **抖刀惩罚**：0.5秒内连续按右键且未成功弹刀 → 弹刀窗口逐次缩小（最低1帧）+ 对敌方架势伤害递减（最低20%）
- 解除惩罚：成功弹刀一次 或 停止按键超过0.5秒（30帧）
- 例外：弹开敌人多段连击时不受惩罚
- **连续弹刀加成**：第1次x1.0 → 第2次x1.2 → 第3次x1.4 → 第4-5次封顶x1.5
- 弹刀窗口分档：轻型攻击12帧，重型攻击6-7帧

### 3.2 弹反节奏（攻防转换）

> 弹反不是防御的终点，而是进攻的起点。

完整攻防循环：
```
我方攻击 → 敌方弹反成功（我方被弹反）→ 我方应切换防御
→ 我方防御 → 卡准时机弹反成功 → 敌方大硬直 → 攻守转换！
→ 我方攻击命中 → 循环继续
```

核心节奏：攻 → 被弹 → 防 → 弹反 → 攻 → 命中 → 攻 → ...

### 3.3 架势条系统（双轨博弈）

- 玩家和弦一郎各有一条架势条（独立于血量）
- 攻击和弹刀互相影响双方架势
- 架势归零 → 崩溃 → 可忍杀（Boss）/ 长时间硬直（玩家）
- 脱战2秒后 → 架势以每秒15%恢复，受击后计时器重置
- 格挡状态下恢复速度减半

### 3.4 三种危的应对

| 危类型 | 特征 | 应对方式 | 奖励 |
|--------|------|---------|------|
| 下段危（红色↓） | 砍脚/低位横扫 | 空格跳跃 | 可踩头输出 |
| 突刺危（红色↓） | 武器向前戳 | Shift识破 | 敌方架势大幅上升 |
| 擒拿危（红色↑） | 投技/抓取 | Shift+方向键垫步 | 无额外奖励 |

识破是默认就会的技能，不需要学习。识破必须正对突刺方向（夹角 < 60°）。

### 3.5 Boss弹刀系统（双向弹刀）

- Boss也能弹玩家的攻击，这是只狼内核
- Boss弹刀窗口比玩家窄：9帧（玩家12帧）
- AI在特定时机进入弹刀姿态，姿态期间有弹刀窗口
- 弹刀成功效果：玩家架势上升x1.5、短暂硬直0.3秒、Boss获得反击窗口
- AI弹刀概率：玩家攻击时40%、连招中60%、Boss低血量25%
- 二阶段弹刀概率整体+10%
- 详细实现见策划案第五章

### 3.6 雷电反击系统（二阶段核心）

- 弦一郎跳起蓄雷（红色危字）→ 雷电下落 → 玩家被击中进入"带电"状态
- 空中按左键 → 接雷（双手举起，雷电停在手中，等待窗口约1秒）
- 再次按左键 → 弹雷（雷电掷回弦一郎，电麻1.5秒，架势大幅上升）
- 失败：未接雷或未及时弹回 → 受到雷电大伤害

### 3.7 回血系统

- 药葫芦10次，每次回复约30%最大生命值
- 喝药时间约0.8秒，期间可被打断
- 不可在受击硬直/崩溃/忍杀演出中使用

## 五、技术架构要点

- **分层状态机（HFSM）**：主角和Boss都使用HFSM
- **数据驱动**：所有战斗参数用ScriptableObject配置
- **事件解耦**：CombatEvents事件系统
- **帧级精度**：弹刀用Physics.OverlapSphere每帧主动检测，不依赖OnTriggerEnter
- **输入缓冲**：150ms缓冲窗口，Queue实现

### 关键类

- `DeflectSystem` — 弹刀判定 + 抖刀惩罚
- `BossDeflectSystem` — Boss弹刀
- `PostureSystem` — 架势条管理
- `DamageCalculator` — 伤害计算
- `LightningCounterSystem` — 雷电反击
- `HitStopManager` — 帧冻结
- `InputBuffer` — 输入缓冲
- `CombatEvents` — 事件系统

## 十、面试高频问题

| 问题 | 回答要点 |
|------|---------|
| 弹刀判定怎么做的？ | OverlapSphere每帧检测 + 12帧窗口 + 攻击类型标记 |
| 抖刀惩罚原理？ | 连续按键计数 → 窗口递减公式 → 成功弹刀/超时重置 |
| 连续弹刀为什么越来越强？ | 加成链数组 x 基础架势伤害 |
| 帧冻结怎么实现？ | HitStopManager控制逻辑暂停，渲染继续 |
| 雷电反击状态流转？ | None→Falling→Charged→Reflected/Failed |
| 为什么用HFSM？ | 代码状态机更灵活，可嵌套子状态 |
| 为什么用ScriptableObject？ | 数据驱动，调参不改代码 |
