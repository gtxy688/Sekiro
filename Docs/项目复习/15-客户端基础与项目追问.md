## 1. C#：struct 为什么仍然会分配？

**项目入口**：[BrainBase](../../Assets/Scripts/Player/Brain/BrainBase.cs)、[PlayerBrain](../../Assets/Scripts/Player/Brain/PlayerBrain.cs)。

值类型和引用类型首先是复制与引用语义的区别，不能背成“struct 必在栈、class 必在堆”。值类型转成它实现的接口时可发生装箱。本项目 `BufferCommand(ICommand)` 和每帧移动命令的接口入口是检查位置；已经装箱的接口引用继续转发不是每经过一层都再装一次箱。

**追问：怎么改？** 可比较带枚举标签的值类型消息、针对高频移动的明确接口、泛型约束调用等方案。但若最后仍存入 `ICommand` 字段，单纯把上游方法改泛型并不能消除最终装箱；方案还要考虑消息种类、可读性与代码体积。先看分配栈再选择。

依据：[Microsoft 装箱与拆箱](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/types/boxing-and-unboxing)。

## 2. 集合：为什么用 HashSet，为什么不能说绝对 O(1)？

**项目入口**：[Hitbox](../../Assets/Scripts/Combat/Hitbox.cs) 的 `hitTargets`、[BossMovePicker](../../Assets/Scripts/Boss/BossMovePicker.cs) 的 `Pick`。

同一目标可能有多个碰撞体且连续多帧被扫到，去重键采用角色对象而非 Collider。HashSet 的查找/插入通常平均 O(1)，冲突和扩容会改变成本，首次增长也不能保证无分配。`Clear` 表示清除元素，不代表释放所有容量。

选招的两遍加权遍历减少临时候选容器；不能只说 O(n) 就忽略每个候选内部的序列和动画状态检查。

**手写练习**：输入包含重复角色标识的命中列表，输出唯一目标；再实现过滤后的权重选择。覆盖空输入、全零权重、冷却过滤、重复命中与随机区间边界，口述时间和空间复杂度。

## 3. 生命周期：为什么接口非空，Unity 对象却已销毁？

**项目入口**：[EncounterScope](../../Assets/Scripts/Combat/EncounterScope.cs) 的 `IsGone`。

Unity 对象有托管包装和引擎对象两层。引擎对象销毁后，托管引用可能还留在集合中。Unity 重载的 `== null` 会检查引擎对象状态；以接口类型直接比较 null 不会自动选中该重载。因此这里先判断普通 null，再匹配到 `UnityEngine.Object` 后做 Unity 判空。

不能简单用 `?.`、`??` 或 `ReferenceEquals` 取代 Unity 生存状态检查。另一方面，纯 C# 的 `ICombatResettable` 实现也不应被强制当成 MonoBehaviour。

**追问：为什么不能依赖倒序重置？** 注册发生在不同组件的 Start，跨组件顺序没有天然保证。`ResetForEncounter` 要可重复、尽量只重置自身状态；倒序遍历不等于拥有确定的业务依赖顺序。

依据：[Unity Object 相等运算符](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Object-operator_eq.html)。

## 4. 事件：解耦后为什么还会内存泄漏？

**项目入口**：[PlayerBrain](../../Assets/Scripts/Player/Brain/PlayerBrain.cs) 的 `BindActions / UnbindActions`、[BossVoiceDirector](../../Assets/Scripts/Audio/BossVoiceDirector.cs) 的 `OnEnable / OnDisable`。

发布者通过委托持有订阅目标；长期存活的静态发布者会保留没有退订的对象引用。普通 C# event 调用通常同步执行，不能把事件总线理解为自动异步队列；慢回调、异常和重入仍会影响调用方。

启用期间监听适合 OnEnable/OnDisable 成对；整个对象寿命监听可以选择初始化/销毁成对。本项目两种方式都有，应解释为什么禁用时还需门禁，而非机械背固定模板。匿名回调不是永远不能退订，但必须保存同一个委托实例；重新写一个 lambda 通常无法移除原订阅。

**口述题**：先画“静态事件→委托→订阅对象”的引用链，再说明重复启用、销毁重建和新 UI 初始化各需要验证什么。

## 5. Unity 更新、动画和物理：一帧究竟发生几次？

**项目入口**：[Hitbox](../../Assets/Scripts/Combat/Hitbox.cs)、[GamePause](../../Assets/Scripts/Mgr/GamePause.cs)、[BrainBase](../../Assets/Scripts/Player/Brain/BrainBase.cs)。

Update 按渲染帧调用，FixedUpdate 按固定时间步调度，一个渲染帧可能没有或有多次固定更新。LateUpdate 用于该帧 Update 后工作，但不自动规定同类回调之间的顺序。动画更新还需考虑 Animator 模式，不要把简化执行图当成所有配置的保证。

`Physics.SyncTransforms` 的职责是同步变换，既不是一次物理模拟，也不是连续碰撞保证。项目用它让查询对应更新后的姿态；每个 Hitbox 都调用的成本需要测量。

`Time.deltaTime` 是受时间缩放影响的帧间隔；缓冲按它扣时间，暂停又可能直接跳过逻辑。讨论 hitstop 时要区分“游戏时间冻结”和“Update 不再执行”。

**扩展题**：Root Motion 和代码移动同时改位置可能冲突；应先跟读 `CharacterBody.OnAnimatorMove` 及移动模块，确认所有权，再设计改变。不要未看执行路径就说“全部放 FixedUpdate”。

依据：[Unity 2022.3 执行顺序](https://docs.unity3d.com/2022.3/Documentation/Manual/ExecutionOrder.html)。

## 6. SO 与资源：配置共享不等于运行状态共享

**项目入口**：[BossMovePicker](../../Assets/Scripts/Boss/BossMovePicker.cs) 的实例白名单参数，以及专题 [09](09-ScriptableObject与配置工具链.md)。

多个角色可以引用同一个 SO。冷却、当前 HP、当前选招等实例状态若写进共享资产，会让多个使用者互相影响。项目把选招白名单作为参数传入，就是可以解释的数据所有权案例。区分资产、运行时创建的 SO 和普通运行对象；创建/销毁与资产保存不是同一个问题。

**扩展题**：异步加载需要处理加载期间切场、引用释放、重复请求与失败重试；使用对象池也要定义借还和复位，不能把所有 Instantiate 替换成池就认为完成资源管理。当前 [WeaponController.SpawnArrow](../../Assets/Scripts/FrameWork/Body/WeaponController.cs) 使用 Instantiate，不能将箭池化写作既有成果。

## 7. 数学：从刀刃火花讲到向量与投影

**项目入口**：[CombatFxPoint](../../Assets/Scripts/Combat/CombatFxPoint.cs) 的 `ClosestOnSegment`。

点 p 在线段 a→b 上的最近点：令 d=b−a；当 d 的平方长度接近零时回退 a，否则 t=Clamp01(Dot(p−a,d)/Dot(d,d))，最近点为 a+t·d。能说明为什么要除长度平方、为什么要 Clamp、零长度为什么不能直接除。

**扩展手写**：判断目标是否在角色前方锥形区域。用水平投影后的方向、距离平方、归一化点积与 cos(半角) 比较；处理目标重合、垂直方向和零向量。该公式练习不代表项目锁定系统已经使用同一算法。

继续追问：叉积可提供左右方向信息；Quaternion 插值用来平滑朝向，但选择 RotateTowards 或 Slerp 还应明确期望是恒定角速度还是插值行为。

## 8. 渲染与 UGUI：使用 URP 之后还要会什么？

这是备考补充，仓库采用 URP 并不能证明已做渲染优化。

- 画出顶点变换、光栅化、片元处理与输出的主流程，区分 CPU 提交和 GPU 执行。
- 解释 Draw Call、状态切换、透明物体过度绘制，以及为什么“Draw Call 少”不保证 GPU 时间低。
- 从血条更新追问 Canvas 重建与动画成本：事件驱动减少逻辑轮询，不等于渲染没有开销。
- 能用 Frame Debugger 查看实际渲染事件，再用 Profiler 判断问题在 CPU、GPU 还是等待；具体合批规则按本项目 URP 版本核实。

**练习产物**：一张实际帧的渲染事件截图，指出一个透明 UI 或特效的成本假设。没有截图前只讲原理，不写“已优化渲染”。

## 9. 项目之外仍要准备的基础

- 算法：数组/链表、栈/队列、哈希、二叉树、二分、排序与复杂度。每天做一道限时 C# 手写题，讲边界输入。
- C#：泛型、委托、闭包、集合枚举、异常、协程和 async/await 的差别。协程不是自动开线程，异步也不保证转到后台线程。
- 按岗位要求补 C++、操作系统和网络：内存所有权、进程线程、TCP/UDP、序列化与同步思路。项目是单机战斗，不能把 Command 当作已经完成网络确定性回放。

每项基础尽量准备“定义→项目例子→边界→小练习”四句话。具体职位未要求的高级技术，优先级低于把现有项目讲清楚。
