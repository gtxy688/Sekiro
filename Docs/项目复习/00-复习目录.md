# 《苇名之刃》项目复习目录

这套文档服务于 Unity 客户端秋招复习。阅读顺序遵循“先看整场战斗，再看模块协作，最后进入实现细节”，不按文件夹机械扫描代码。

## 27 届秋招：从这里开始

本轮校对日期：2026-09-05。项目版本为 Unity **2022.3.62f3**，包配置为 URP **14.0.12**、Input System **1.14.2**、Cinemachine **2.10.7**，来源分别是 `ProjectSettings/ProjectVersion.txt` 和 `Packages/manifest.json`。复习 API 时优先看对应版本。

- [14：秋招复习路线与验收标准](14-秋招复习路线与验收标准.md)：按剩余时间安排复习，每次学习都有输出。
- [15：客户端基础与项目追问](15-客户端基础与项目追问.md)：把项目串到 C#、生命周期、物理、数学、渲染和资源基础。
- [16：性能验证与故障排查实战](16-性能验证与故障排查实战.md)：把“可以优化”变成可复现、可度量的实验。
- [17：源码导航与模拟面试](17-源码导航与模拟面试.md)：专题入口、回答要点、现场练习和复盘记录。

**证据分层**：源码能证明某条实现存在；场景装配与运行录像才能证明它实际触发；性能收益必须有测量记录。本轮是静态源码与文档核对，没有运行 Unity、构建或采集 Profiler；文中的实验均为待执行练习。

以下优先级是围绕本项目制定的备考建议，不是企业题频统计，也不代表已核实任何公司的 27 届招聘日程。投递资格、毕业时间范围和截止时间请以目标岗位公告为准。

每篇尽量回答四个问题：

1. 这个模块在整场 Boss 战中处于什么位置？
2. 一次真实行为如何经过它？
3. 为什么采用当前方案？
4. 面试官继续追问时，应该承认哪些边界和代价？

## 推荐复习方式

- 第一遍：只读 01，能口述整场 Boss 战。
- 第二遍：读 02—04，理解“谁决策、谁执行”。
- 第三遍：读 05—08，把演示视频中的每个战斗现象对应到代码链路。
- 第四遍：读 09—12，补齐数据驱动、Editor API、表现解耦和战斗生命周期。
- 面试前：读 13，并练习每篇的“面试追问梯度”。
- 每轮读完：到 17 闭卷回答，再用 16 的步骤验证一个问题；只阅读不算通过。

每篇分为两层：

- 正文：理解系统边界、真实调用链与设计原因。
- 面试准备：按“基础概念 → 项目实现 → 方案取舍 → 扩展设计 → 故障排查”继续追问。

不要追求背下所有类名和 API。先能说清因果关系，再记住支撑回答的关键入口。
