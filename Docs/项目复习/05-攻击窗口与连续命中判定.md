# 攻击窗口与连续命中判定

这一篇回答：为什么不用一直开启的 Trigger，而是用动画时间窗和连续空间扫描。

## 1. 完整调用链

```text
AttackState 播放攻击动画
→ AttackAnimClock 读取当前动画秒数
→ 命中脉冲进入有效区间
→ CharacterBody.EnableWeaponHit
→ WeaponController 绑定 AttackConfig
→ Hitbox.Enable
→ LateUpdate 连续扫描
→ 找到 Hurtbox
→ CombatManager.ReportHit
→ CombatResolver.ReportHit
→ target.ReceiveHit
```

攻击状态负责“什么时候开判定”，Hitbox 负责“空间中扫到了谁”，CombatResolver 负责“把什么伤害交给谁”。

## 2. 为什么判定跟随攻击窗口

武器 Collider 如果一直有效，会出现：

- 前摇阶段刀还没挥出就打到贴身目标。
- 收招阶段刀已停下仍重复造成伤害。
- 同一段动画难以配置多次攻击。

`AttackConfig.hitPulses` 用多个 `[start, end)` 区间描述一条动画里的出伤脉冲。`AttackStateBase` 每帧读取动画播放秒数，只在脉冲内开启对应 Hitbox。

动画事件仍可作为可选入口，但运行时真正的时间控制来自配置化窗口，便于统一编辑和校验。

## 3. SphereCast 解决高速穿透

武器骨骼由动画直接移动。一帧在目标左侧，下一帧可能已经到右侧，单看当前位置会漏掉中间经过的目标。

`Hitbox.LateUpdate` 保存上一帧位置，用 `SphereCastAll` 扫过：

```text
lastCastPos
→ 当前 transform.position
```

这相当于给武器采样点的前后帧连线增加厚度，减少高速挥刀的跨帧漏检；它没有完整覆盖刀身旋转扫过的体积，不能保证任意帧率和姿态下绝不漏判。

## 4. Overlap 解决起点与贴身漏检

要区分 `SphereCast` 与本项目实际调用的 `SphereCastAll`。Unity 2022.3 文档说明：`SphereCastAll` 对起始重叠可返回零距离、零向量命中点，不能背成“起点在内部就一定查不到”。另外，本项目位移太小时根本不执行 Cast；贴身时刀尖轨迹也可能从身体外侧经过。见 [SphereCastAll 官方说明](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Physics.SphereCastAll.html)。

因此每帧额外执行：

- `OverlapSphereNonAlloc`：检查刀尖当前位置。
- `OverlapCapsuleNonAlloc`：检查刀柄到刀尖整段。

两者互补：

- SphereCast 负责上一帧到这一帧的连续路径。
- Overlap 负责当前位置、起点重叠和贴身刀身覆盖。

## 5. 为什么在 LateUpdate 扫描

当前意图是在通常动画更新后读取骨骼姿态：Hitbox 在 `LateUpdate` 中先调用 `Physics.SyncTransforms()`，再读取武器位置并查询。`SyncTransforms` 同步 Transform 变化到物理引擎，不负责推进动画或补齐历史轨迹。实际先后还受 Animator 更新模式及其他脚本影响；同属 LateUpdate 的两个脚本也不能默认有指定顺序。参见 [Unity 执行顺序](https://docs.unity3d.com/2022.3/Documentation/Manual/ExecutionOrder.html)。

## 6. 单次攻击去重

`hitTargets` 是 `HashSet<CharacterBody>`。同一判定窗口中，第一次命中目标后记录，后续帧再次扫到不会重复结算。

新攻击脉冲开始时会重置命中记录，因此一条多段攻击仍可在不同脉冲中再次命中同一目标。

拼刀另外使用 `clashedPartners` 去重，并只允许 InstanceID 较小的一方上报，防止双方 Hitbox 同时报告导致架势结算两次。

## 7. Hitbox 与 Hurtbox

- Hitbox 属于攻击者，保存 Owner 和当前 `AttackConfig`。
- Hurtbox 属于受击者，只负责暴露 Owner。
- CombatResolver 从两者取得攻击者、目标和伤害配置，不关心谁是玩家、谁是 Boss。

这种无阵营特判的结算层更容易复用于其他敌人。

## 8. 方案代价

- 每个有效攻击帧都进行物理查询。
- `SphereCastAll` 返回数组，是分配排查入口；是否构成瓶颈需要 Profiler 数据。现有 Overlap 复用长度为 16 的缓冲区，返回数量达到容量时应怀疑结果被截断，不能宣称 NonAlloc 自动保证结果完整。
- 参数过大会产生“刀没碰到也命中”，过小又会漏判。
- 连续扫描只能解决空间漏检，不能替代正确的攻击时间窗。

## 面试回答

> 攻击状态按 Animator 播放秒数开启配置化 Hitbox。判定时用武器前后帧位置做 SphereCast，避免高速挥刀跨帧穿透，再用 Sphere 和 Capsule Overlap 补偿从碰撞体内部出发及贴身刀身漏检；单个攻击脉冲用 HashSet 对目标去重。

回答时先明确“时间连续性”和“空间连续性”是两个问题：攻击窗口解决时间，Cast/Overlap 解决空间。

源码入口：[Hitbox.cs](../../Assets/Scripts/Combat/Hitbox.cs) 的 `Enable / LateUpdate / FillOverlapping / TryHit / TryClash`。刀尖取本物体位置，刀柄取父物体位置；这依赖实际挂点，父物体不一定天然就是刀柄。`hitTargets.Add` 在上报结算前执行，因此去重记录表示“该窗口已尝试上报此目标”，并不等价于“已经成功扣血”。

**验证题**：分别演示静止重叠、贴身挥刀、大角度旋转、一次脉冲多帧命中、多脉冲命中；保存当前动画秒数、脉冲索引和查询结果。低帧率跨过整个短窗口属于额外时间采样问题，需要检查窗口驱动代码并运行验证，空间 Cast 本身不能证明它已解决。
