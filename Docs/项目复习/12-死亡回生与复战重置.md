# 死亡、回生与复战重置：战斗生命周期

这一篇回答：玩家生命归零后为什么还不一定结束，以及如何在不重载场景的情况下恢复整场战斗。

## 1. 玩家死亡判定

`CombatStats.TakeDamage` 将 HP 扣到零后进入 `HandleDeath`：

- 停止当前攻击和霸体。
- 关闭武器判定。
- 有剩余回生次数时发布回生可用事件，并进入可回生死亡状态。
- 没有回生时发布真正死亡事件。

## 2. RevivePendingState

玩家先播放倒地动画，躺平并完成画面压暗后才开放选择：

- `AttackCommand`：开始回生。
- `DeflectCommand`：放弃，进入真正死亡。

状态不自动超时，玩家可以明确选择。

## 3. 回生

选择回生后：

```text
ReviveRemaining - 1
→ HP 回满
→ 架势清零
→ 清除崩解
→ 发布 HP / Posture / Revived
→ 播放 Revive 动画
→ 回到 GroundedState
```

Boss 在玩家失能时停止正常主动攻击。收到玩家回生事件后，等待玩家站起，再切入专门的后撤状态，随后才恢复选招，避免玩家起身瞬间被贴脸攻击。

## 4. 真正死亡

玩家没有回生或主动放弃时：

- 进入 DeadState 下的真正死亡分支。
- 输入被阻断。
- UI、音频和流程层收到死亡事件。
- Boss 不再执行正常攻击循环。

## 5. Boss 的“死亡”不同

Boss 普通 HP 归零与玩家死亡不是完全相同的终点。项目核心胜利路径是：

```text
Boss 架势崩解
→ 玩家忍杀
→ ClearLife
→ 有命继续战斗 / 无命触发 Victory
```

命数是 Boss 战阶段推进资源；回生次数是玩家死亡后的恢复资源，两者不要混淆。

## 6. 为什么需要 EncounterScope

重载场景会自然销毁所有运行时对象，但“原地复战”不会。此时可能残留：

- HP、架势、命数和回生次数。
- 状态机当前状态和角色位置。
- Boss AI 冷却、正在执行的节点与回生礼让阶段。
- 忍杀或投技的活动演出。
- 顿帧、输入门、锁定与 UI 状态。

`EncounterScope` 定义一场战斗的参与者，并收集所有 `ICombatResettable`。

## 7. ResetAll 契约

F8 调试入口调用 `EncounterScope.ResetAll()`。每个组件只重置自己的状态，并遵守：

> ResetForEncounter 必须与执行顺序无关，而且可以重复调用。

Unity 不保证不同组件 `Start` 的顺序，因此重置方法不能依赖“另一个组件已经先恢复”。初始数值应从稳定的 Config 读取。

## 8. 当前边界

- F8 是临时验收入口，不是正式重新挑战 UI。
- EncounterScope 不负责生成 Boss、加载场景或编排连战。
- 它提供的是一场战斗的参与者边界与重置能力。

### 项目实现

### 方案取舍

6. 为什么原地 ResetAll，而不是直接重新加载场景？
7. 为什么 ResetForEncounter 要求顺序无关和幂等？

### 扩展设计

9. 如果正式加入“重新挑战”按钮，哪些 UI 和流程需要接到 ResetAll？
10. 如果做连续 Boss 战，EncounterScope 应负责什么、不应负责什么？

### 故障排查

11. 复战后 Boss 不出招，应检查哪些 AI 临时状态？
12. 复战后角色仍锁定在忍杀，说明哪个场景级事务没有清理？

回答复战时不要说“把变量都重置”。要强调战斗作用域、组件自主管理、顺序无关和可重复调用的契约。
