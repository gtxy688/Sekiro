# 闪避、危字攻击与识破

这一篇回答：闪避无敌帧、突刺识破和投技为什么都在命中响应阶段判断。

## 1. 闪避的执行

玩家发出 `DodgeCommand` 后，当前地面状态允许时切入 `DodgeState`。

- 位移由闪避动画 Root Motion 驱动。
- 代码负责记录闪避总时长和无敌帧时长。
- 锁定状态下根据输入方向选择前、后、左、右垫步动画。
- 闪避结束后，根据当前移动输入回到 Idle 或 Move。

## 2. 无敌帧

命中到达 `DodgeState.OnHitReceived` 时：

```text
dodgeTimer <= DodgeIFrame
→ 返回 true
→ ReceiveHit 停止向下结算
→ 不扣血、不涨架势、不进入受击
```

无敌帧不是关闭 Hurtbox，而是当前状态对命中返回“已处理”。这样 Hurtbox 可以持续存在，命中链路仍然统一。

## 3. 危字攻击的数据

`AttackConfig.Perilous` 或 Boss 段级 `BossMoveWindow.perilous` 标记危字类型。攻击状态开始时发布危字事件，UI 显示提示；真正命中时，类型随 `HitData` 传给目标。

当前主要类型包括突刺和投技。危字提示属于表现，是否成功反制仍由命中时的目标状态决定。

## 4. 识破成立条件

进入 `DodgeState` 时会记录当时是否没有方向输入：

```text
无方向垫步
+ 命中是 PerilousType.Thrust
→ 切入 MikiriCounterState
→ 吞掉这次普通伤害
```

带方向垫步只享受无敌帧，不触发识破。这样避免后撤或侧闪时意外踩刀，也避免成对动画朝向异常。

## 5. 为什么先判断识破，再判断无敌帧

突刺在无方向垫步中命中时，应优先进入识破演出，而不是仅仅被无敌帧吞掉。

因此 `DodgeState.OnHitReceived` 的顺序是：

```text
先判断是否满足 Mikiri
→ 不满足再判断普通闪避无敌帧
→ 都不满足则返回 false，进入普通受击
```

规则优先级决定了同一次命中最终落入哪个机制。

## 6. 识破结果

`MikiriCounterState` 负责识破演出和状态锁定，并向攻击者累计大量架势。若这一击使 Boss 架势达到上限，崩解来源记录为 `Mikiri`，后续选择识破忍杀动画。

识破不是“按下闪避就立即判断成功”，必须等突刺 Hitbox 真正命中，才能确认时机和对象。

## 7. 投技

危字投技未被当前状态拦截时，`ReceiveHit` 先完成伤害结算，再由 `CombatManager.TryStartGrabThrow` 尝试建立双方成对投技演出。

处决和投技都由 `DuelDirector` 使用一个活动演出槽管理，因为两种成对演出不应该同时发生。

## 8. 叶子状态查询问题

主状态机当前值是 `GroundedState`，不是 `DodgeState`。外部命中逻辑不应写：

```csharp
body.MainStateMachine.CurrentState is DodgeState
```

正确方案是让 `OnHitReceived` 自动路由到当前叶子状态。外部关心“命中是否被处理”，不需要知道内部状态类型。
