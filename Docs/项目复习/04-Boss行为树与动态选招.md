# Boss 行为树与动态选招

这一篇回答：Boss 怎样选择下一步行为，又怎样把选择交给角色执行层。

## 1. 行为树与 HFSM 的分工

- 行为树回答：“下一步选什么？”
- HFSM 回答：“角色现在正在做什么，这个行为能否执行？”

Boss 的行为树不会直接负责武器判定和受击生命周期。它选择走位或招式，再交给 `CharacterBody + HFSM`。

## 2. 轻量行为树组成

- `Node`：节点基类，返回 `Running / Success / Failure`。
- `Selector`：按优先级寻找第一个可以执行的子节点。
- `Sequence`：前一步成功后才执行下一步。
- `ConditionNode`：封装条件判断。
- `Blackboard`：保存冷却、当前选择和共享运行数据。
- `BT_*` 叶子：选招、执行招式、追击、喝药惩罚等具体行为。

`Running` 记忆很重要：一段招式开始后，树下一帧应继续执行它，而不是每帧重新抽招。

注意当前 [Selector.cs](../../Assets/Scripts/Boss/BehaviourTree/Selector.cs) **仅为实现 `ISelectorLock` 的直接子节点保存 Running 索引**。普通追击节点返回 Running，不会因此锁住下一帧的选择；否则追击会阻挡更高优先级反应。锁定子节点续跑时会先于正常优先级遍历，所以也不能笼统说“高优先级每帧都能抢占”。续跑结束后，代码会清除索引并重新从头遍历，调试时还应注意同次 Evaluate 中节点是否再次被访问。

## 3. Boss 每帧的宏观顺序

`BTBrain.Update` 先处理全局状态：

- Boss 已被击败：停止树和移动。
- 忍杀锁定或被弹反：暂停树并清理正在执行的招式。
- 玩家倒地或失能：停止主动攻击，改为绕行。
- 玩家正在回生：等待起身并后撤。
- 开场语音期间：可以走位，但不主动出招。
- 正常情况：执行行为树根节点。

## 4. 主树优先级

当前树可概括为：

```text
崩解/硬直检查
→ 交锋反应
→ 玩家喝药惩罚
→ 主动选招
→ 没有可用招式时追击或绕行
```

Selector 的顺序就是行为优先级。高优先级节点能运行时，后续走位节点不会执行。

## 5. 动态选招

`BossMovePicker` 为每个招式计算是否可选以及权重：

- `Active` 层招式的距离必须落在 `minRange / maxRange`；当前 `Weight` 的距离过滤只作用于这一层，不能泛化到所有反应招式。
- 招式不能处于冷却。
- Animator 必须真的存在所需状态。
- `weight` 必须大于零。
- 特殊条件可检查 Boss HP、架势、连续被弹反次数或玩家是否倒地。

通过筛选的招式按权重随机抽取。权重不是“百分比”，而是候选招式之间的相对概率。

源码入口：[BossMovePicker.cs](../../Assets/Scripts/Boss/BossMovePicker.cs) 的 `Pick / Weight`。`Pick` 两遍遍历：第一遍累加有效权重，第二遍按随机落点选区间，没有为候选另建列表。若每个候选只需常数工作则为 O(n)；实际还会检查动画序列，精确分析需计入这些检查。有效权重全为零时返回 null，由调用方处理无可选招式。

**口算题**：有效权重为 1、3 时概率为 1/4、3/4；第二招进入冷却后第一招概率为 1。不能先对包含无效招式的总权重抽签、再简单丢弃结果，否则可能改变分布或产生无动作帧。

## 6. 招式如何执行

`BT_PickActive` 选出 `BossMoveEntry` 后交给 `BT_ExecuteMove`：

```text
选择一个可播放动画序列
→ 取得当前段 BossMoveWindow
→ BossAttackBaker 生成运行时 AttackConfig
→ CharacterBody.StartAttack
→ AttackState 执行动画、时间窗和判定
```

首段通常走 `AttackCommand`。已经确认执行的连续招式后续段，可以受控地直接切入 `AttackState`，避免先经过 Idle 破坏动画衔接。

所以准确说法是：

> 玩家输入与 Boss AI 复用同一个执行层；常规意图优先走 Command，已确认的连续流程可以走语义化切换入口。

## 7. 当前阶段系统的真实边界

Boss 配置了多条命，但当前 `BossMovePicker` 没有根据 `LivesRemaining` 切换招式池。它会根据 HP、架势和战斗状态调整候选，但不能把第一条命后的战斗描述成完整的第二阶段 AI。

## 8. 为什么自研轻量行为树

当前树规模只需要选择器、序列、条件、黑板和少量叶子，自研能展示对运行状态、优先级和黑板的理解，也避免作品依赖付费插件。

商业项目中如果树规模扩大、需要可视化编辑和运行调试，应考虑成熟工具或更完整的团队框架。

## 面试追问梯度

### 基础概念

1. Selector、Sequence 的返回规则是什么？
2. Running、Success、Failure 分别表示什么？
3. Blackboard 解决了什么问题？

### 项目实现

4. Boss 选招怎样同时考虑距离、冷却、权重和特殊战况？
5. 一段招式 Running 时，为什么不能每帧重新抽招？
6. 玩家倒地或回生时，行为树如何改变行为？

### 方案取舍

7. 为什么行为树负责决策、HFSM 负责执行？
8. 为什么自研，而不是使用 Behavior Designer？
9. 权重随机和固定优先级各适合什么行为？

### 扩展设计

10. 如果加入阶段招式池，你会把阶段条件放在哪里？
11. 如果树扩展到上百节点，怎样提供运行时可视化和调试？

### 故障排查

12. Boss 一直追击却不出招，应依次检查哪些过滤条件？
13. Boss 被打断后继续播放旧连招，说明哪个 Running 状态没有清理？

回答动态选招时必须区分：过滤决定“能不能进候选”，权重决定“候选之间怎么随机”。
