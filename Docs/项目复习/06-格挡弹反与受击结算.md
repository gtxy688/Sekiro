# 格挡、弹反与受击结算

这一篇回答：同一次敌方攻击，为什么会产生普通受击、格挡或完美弹反三种结果。

## 1. 命中不会立刻扣血

`CombatResolver` 把伤害配置包装成对 `CharacterBody.ReceiveHit` 的调用。目标先执行：

```text
Boss 被动防御检查
→ 当前 HFSM 状态 OnHitReceived
→ 状态未拦截
→ CombatStats 扣血与增加架势
→ 根据结果进入受击、崩解或死亡
```

格挡与弹反都发生在“普通伤害结算之前”。

## 2. 格挡状态

玩家按下防御后，`DeflectCommand` 使地面叶子状态切入 `DeflectState`。

进入状态后的早期时间属于完美弹反窗口；窗口结束后如果玩家仍按住防御，则继续保持普通格挡。两者共用一个防御状态，但结算不同。

普通格挡通常表现为：

- 阻止或降低生命伤害。
- 防御者按攻击的架势伤害比例增加自身架势。
- 播放格挡受击动画、火花和音效。
- 重攻击可能触发更强的格挡硬直。

## 3. 完美弹反

攻击在弹反窗口内到达时：

- 本次普通伤害被拦截。
- 攻击者增加 `DeflectPostureGain` 等架势。
- 攻击者进入被弹反硬直或反应流程。
- 发布武器弹反事件，驱动音效、火花、顿帧和震屏。

项目还记录连续弹反次数，Boss 可以在交锋次数达到条件后解锁特定反制招式。

## 4. Boss 的被动格挡与弹反

玩家连续压制 Boss 时，Boss 不一定需要行为树提前选中“格挡节点”。`CharacterBody.TryPassiveDeflect` 在命中入口先判断 Boss 是否具备被动防御资格。

连续格挡达到配置阈值后，下一次防御可升级为完美弹反。这使攻防转换发生在命中响应层，而不是要求 AI 精确预测玩家每一刀。

## 5. 普通受击

如果当前状态没有拦截：

```text
CombatStats.TakeDamage
→ 扣生命
→ 增加架势
→ 检查死亡
→ 检查本次是否刚好打崩架势
→ 未死亡、未崩解时进入 StunnedState
```

玩家受击动画按 `HitGrade` 区分 Light、Mid、Heavy；Boss 仍主要根据 Knockback 选择普通或重受击表现。

## 6. 架势与生命是并行结果

一刀可以同时造成生命伤害和架势伤害。即使生命没有归零，架势也可能先达到上限并进入崩解；反过来，生命归零会直接进入死亡流程。

完美弹反时自己的架势可以继续累积或刷新战斗时间，但通过 `allowBreak=false` 保证不会因完美弹反自身而崩解，符合项目的战斗规则。

## 7. 为什么不在 CombatResolver 里写格挡判断

CombatResolver 不知道目标当前处于什么行为。把格挡、弹反写进去会迫使结算器依赖具体状态类型。

现在由状态处理命中：

- 状态最清楚自己的时间窗口。
- 新增防御行为时不必扩大一个全局 switch。
- 玩家与 Boss 可以复用同一条 `ReceiveHit` 链路。

## 8. 代价

- 结果分散在状态和 `CombatStats` 两层，调试需要追踪返回值。
- 防御窗口、受击等级和表现动画配置较多。
- 被动防御放在 `ReceiveHit` 入口之前，是针对 Boss 攻防体验的明确规则，需要在面试时讲清优先级。

## 面试追问梯度

### 基础概念

1. 格挡和完美弹反在数值结果上有什么区别？
2. 为什么弹反窗口是状态内的时间条件？

### 项目实现

3. 一次命中如何从 `CombatResolver` 到达 `DeflectState`？
4. 为什么 Boss 被动防御要先于普通状态受击？
5. `allowBreak=false` 解决了什么战斗规则？

### 方案取舍

6. 为什么不在 CombatResolver 中写一个格挡/弹反大 switch？
7. Boss 被动弹反放在命中响应层，会带来什么耦合？

### 扩展设计

8. 如果加入盾牌、方向格挡或体力消耗，规则应该放在哪里？
9. 如果不同攻击有不同可格挡类型，HitData 需要增加什么语义？

### 故障排查

10. 画面播放弹反特效但攻击者没进硬直，怎样追事件与状态链？
11. 玩家按住格挡却偶尔裸受击，怎样判断是窗口、状态退出还是危字规则？

回答时先讲“命中先询问状态，未拦截才普通结算”，再分别解释格挡和弹反，不要把表现特效当作结算依据。
