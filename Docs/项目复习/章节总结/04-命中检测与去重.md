## 1. 开启与关闭判定：WeaponController → Hitbox

### 1. 调用链
上一篇（`03-一次攻击怎样从开始到结束`）讲到，`AttackStateBase.ApplyHitbox` 在动画时钟进入脉冲区间 `[start, end)` 的首帧调用 `body.EnableWeaponHit(config)`，在离开脉冲的首帧或 `OnExit` 时调用 `body.DisableWeaponHit()`。

这两个调用经 `CharacterBody` 转发给 `WeaponController`，再操作具体的 `Hitbox` 组件：

```text
AttackStateBase.ApplyHitbox() / OnExit()
  ├─ 开启：CharacterBody.EnableWeaponHit(config)
  │    └─ WeaponController.EnableWeaponHit(config)
  │         ├─ ResolveHitbox(config.HitboxSlot)    按槽位选刀 (Weapon)、肘 (Elbow) 或脚 (Kick)
  │         ├─ target.SetConfig(config)            写入本段伤害配置，清空 hitTargets
  │         ├─ target.Enable()                     isActive = true，记录起点 lastCastPos，清空去重集合
  │         └─ CombatEventBus.TriggerAttackSwingStart(body)   通知表现层开启刀光
  │
  └─ 关闭：CharacterBody.DisableWeaponHit()
       └─ WeaponController.DisableWeaponHit()
            ├─ target.Disable()                    isActive = false，清空 config 与去重集合
            └─ CombatEventBus.TriggerAttackSwingEnd(body)     通知表现层结束刀光
```

### 2. WeaponController 源码
角色身上可以有多个攻击部位（手里的刀 `weaponHitbox`、拳肘 `elbowHitbox`、脚 `kickHitbox`）。`WeaponController` 根据当前招式配置的 `HitboxSlot` 选出对应的 `Hitbox` 开启；如果切换了槽位，会先把上一个槽位关掉：

```csharp
// WeaponController.cs
// 为选中的 Hitbox 绑定本招配置并开启扫描；弓段等无近战窗口的配置直接跳过。
public void EnableWeaponHit(AttackConfig config)
{
    // 弓段 / 假红条：即使动画事件误调也不开刀。
    if (!AttackWindowSync.CanMeleeHit(config.hitPulses))
        return;
    Hitbox target = ResolveHitbox(config.HitboxSlot);

    // 刀、肘和脚不能残留同时判定；切槽时先关上一槽，再把本招配置交给新槽。
    if (ActiveHitbox != null && ActiveHitbox != target)
        ActiveHitbox.Disable();

    target.SetConfig(config);
    target.Enable();
    ActiveHitbox = target;
    CombatEventBus.TriggerAttackSwingStart(body);
}

// 关闭攻击扫描并通知表现层收尾；不是销毁或隐藏武器模型。
public void DisableWeaponHit()
{
    Hitbox target = ActiveHitbox != null ? ActiveHitbox : Weapon;
    target.Disable();
    ActiveHitbox = null;
    CombatEventBus.TriggerAttackSwingEnd(body);
}

Hitbox ResolveHitbox(AttackHitboxSlot slot)
{
    if (slot == AttackHitboxSlot.Elbow)
        return body.elbowHitbox;

    if (slot == AttackHitboxSlot.Kick)
        return body.kickHitbox;

    return Weapon;
}
```

### 3. Hitbox 的字段与 Enable / Disable 源码
在场景里，角色和武器的碰撞结构是这样摆放的：

- **受击方身体（`Hurtbox`）**：角色身体上挂着 CapsuleCollider（胶囊碰撞体）和 `Hurtbox` 脚本，`hurtbox.Owner` 指向该角色的 `CharacterBody`；
- **攻击方武器（`Hitbox`）**：武器上不挂矩形 BoxCollider，也不用 Unity 的 `OnTriggerEnter` 触发器回调。`Hitbox` 脚本挂在武器的**刀尖节点**上（`transform.position` 是刀尖位置），而它的父节点 `transform.parent` 是**刀柄节点**（`transform.parent.position` 是刀柄位置）：

```text
武器骨骼层级：
  [父节点 transform.parent：刀柄 hilt] ═══════════════ [当前节点 transform：刀尖 tip（挂 Hitbox 脚本）]
                                          整段刀身
```

当 `WeaponController` 调用 `target.SetConfig(config)` 和 `target.Enable()` 时，`Hitbox` 把开关 `isActive` 设为 `true`，把当前刀尖位置记入 `lastCastPos` 作为下一帧扫掠的起点，并清空去重集合：

```csharp
// Hitbox.cs
public class Hitbox : MonoBehaviour
{
    [Header("判定参数")]
    public float castRadius = 0.1f;   // 扫描球半径（大约等于武器"粗细"）
    [Tooltip("柄到尖的刀身半径。贴身时刀尖在人外侧，只扫尖会漏")]
    public float shaftRadius = 0.3f;
    public LayerMask targetLayers;    // 能打到的层：对方 Hurtbox / 对方 Hitbox（拼刀）

    private CharacterBody owner;
    private AttackConfig config;          // 当前招式的伤害配置
    private Vector3 lastCastPos;          // 上一帧的武器位置（扫描起点）
    private bool isActive;                // 由 AttackState Enable/Disable

    // 已命中记录：防止一次挥砍对同一目标多次结算
    private readonly HashSet<CharacterBody> hitTargets = new HashSet<CharacterBody>();
    // 拼刀去重：同一判定窗内对同一 Hitbox 只结算一次；且只让 InstanceID 较小方上报，避免双方各报一次
    private readonly HashSet<Hitbox> clashedPartners = new HashSet<Hitbox>();
    private readonly HashSet<CharacterBody> blockedUntilExit = new HashSet<CharacterBody>();
    private readonly HashSet<CharacterBody> overlappingThisFrame = new HashSet<CharacterBody>();
    private readonly Collider[] overlapBuf = new Collider[16];

    // 攻击状态为每个有效脉冲绑定伤害配置，并清除上一刀的命中记录。
    public void SetConfig(AttackConfig config)
    {
        this.config = config;
        hitTargets.Clear();
    }

    public void Enable()
    {
        // 无有效近战窗口的弓段或占位脉冲不启用扫描。
        if (!AttackWindowSync.CanMeleeHit(config.hitPulses))
            return;
        isActive = true;
        Physics.SyncTransforms();
        lastCastPos = transform.position;
        hitTargets.Clear();
        blockedUntilExit.Clear();
        clashedPartners.Clear();
    }

    public void Disable()
    {
        isActive = false;
        config = null;
        hitTargets.Clear();
        blockedUntilExit.Clear();
        clashedPartners.Clear();
    }
```

## 2. 每帧扫描：Hitbox.LateUpdate 与三种几何形状查询

### 1. Hitbox.LateUpdate 内部的完整调用树
`Enable()` 把 `isActive` 设为 `true` 后，Unity 每帧在 `Update`（动画改写骨骼位置）之后调用 `Hitbox.LateUpdate()`。

先看清 `LateUpdate` 内部从扫描到上报的完整调用树，后面所有小函数都挂在这棵树上：

```text
Hitbox.LateUpdate()                                        每帧检测主入口（仅 isActive == true 时执行）
  ├─ Physics.SyncTransforms()                              把本帧动画改过的骨骼位置同步到物理引擎
  │
  ├─ 【第 1 步：刀尖位移扫掠】
  │    Physics.SphereCastAll(lastCastPos → currentPos)     查询 1：上一帧刀尖到本帧刀尖拉出一条球形管道
  │      └─ ProcessHits(hits)                              遍历扫到的所有 RaycastHit
  │           └─ ProcessCollider(col, hitPoint)            判断扫到的是身体 Hurtbox 还是武器 Hitbox
  │                ├─ 扫到对方 Hurtbox → TryHit(hurtbox.Owner, hitPoint)
  │                │                      └─ CombatManager.Instance.ReportHit(...)     上报命中角色
  │                └─ 扫到对方 Hitbox  → TryClash(other, hitPoint)
  │                                       └─ CombatManager.Instance.ReportClash(...)   上报双方拼刀
  │
  ├─ 【第 2 步：当前帧原地重叠补检】
  │    FillOverlapping(overlappingThisFrame)
  │      ├─ Physics.OverlapSphereNonAlloc(tip)             查询 2：当前帧刀尖原地放一个小球
  │      │    └─ AddOverlapping(dest, count)               提取 Hurtbox.Owner 放入 overlappingThisFrame
  │      └─ Physics.OverlapCapsuleNonAlloc(hilt → tip)     查询 3：从刀柄到刀尖包一个套住整把刀身的胶囊体
  │           └─ AddOverlapping(dest, count)               提取 Hurtbox.Owner 放入 overlappingThisFrame
  │
  ├─ foreach target in overlappingThisFrame:
  │    └─ TryHit(target, currentPos)                       把第 2 步重叠查到的角色同样交给 TryHit
  │         └─ CombatManager.Instance.ReportHit(...)       上报命中角色
  │
  └─ lastCastPos = currentPos                              把本帧刀尖位置存为下一帧的起点
```

### 2. 三种几何查询在 3D 空间里分别是什么形状？为什么要三个一起用？
武器本身没有挂碰撞盒，而是每帧在 `LateUpdate` 里用代码在空间中画出**三个几何形状**去探测周围的碰撞体：

#### 查询 1：刀尖帧间移动拉出的“球形管道”（`Physics.SphereCastAll`）
- **在空间里是什么形状**：
  在上一帧刀尖的位置 `lastCastPos` 放一个半径 `castRadius`（`0.1m`）的小球，沿着直线推到这一帧刀尖的位置 `currentPos`。小球滑过的轨迹，在两帧刀尖之间拉出了一条**胶囊状的圆管**。
- **为什么需要它（防高速挥刀穿模）**：
  如果只在每一帧刀尖停留的点测一下，当挥刀动作很快或遇到掉帧时，上一帧刀尖还在敌人身体左边，下一帧刀尖已经直接跳到了敌人身体右边，中间没有任何一帧停在敌人身上，就会直接穿过去漏判。把上一帧刀尖和这一帧刀尖连成一条圆管扫过去，只要敌人挡在两帧之间的路径上，就一定会被这条管道扫中。

```text
【查询 1：SphereCastAll（两帧刀尖之间拉出球形管道）】
  上一帧刀尖 (lastCastPos)                     本帧刀尖 (currentPos)
         ( ● ) ═══════════════════════════════════► ( ● )
                 半径 castRadius (0.1m) 的扫掠圆管
                 （即使一帧跨过敌人身体，管道也会扫中中间的敌人）
```

#### 查询 2：本帧刀尖原地放一个“静止小球”（`Physics.OverlapSphereNonAlloc`）
- **在空间里是什么形状**：
  不拉轨迹，直接在当前帧刀尖 `transform.position` 原地放一个半径 `castRadius`（`0.1m`）的球体，把球体内部重叠的所有碰撞体取出来。
- **有了查询 1 为什么还要它（防起点已经在敌人身体里）**：
  Unity 的 `SphereCastAll` 有一个底层机制：如果出发起点那颗球**一开始就已经嵌在敌人的碰撞体肚子里面**，`SphereCastAll` 算不出“从外部撞入表面”的交点，会直接漏掉这个碰撞体（比如连招第二刀刚开启 `Enable()` 时，刀尖本来就还插在贴身敌人的身体里）。因此在当前帧刀尖原地放一颗重叠球，专门把已经和刀尖叠在一起的敌人查出来。

```text
【查询 2：OverlapSphereNonAlloc（当前刀尖原地放一颗球）】
                     ╭───╮
                     │ ● │  ← 在本帧刀尖 (tip) 原地检测半径 0.1m 球体内部
                     ╰───╯    （解决起点已嵌在敌人碰撞体内部时 SphereCast 漏检）
```

#### 查询 3：从刀柄到刀尖包住整把刀身的“圆柱胶囊”（`Physics.OverlapCapsuleNonAlloc`）
- **在空间里是什么形状**：
  以刀柄 `hilt`（`transform.parent.position`）为一端，以刀尖 `tip`（`transform.position`）为另一端，半径设为 `shaftRadius`（`0.3m`），在当前帧沿着整把刀包出一个**套住整段刀身的胶囊体**。
- **有了前两个刀尖查询为什么还要它（防贴身站在挥刀内侧漏判）**：
  查询 1 和查询 2 测的都只是**“刀尖”那一个点**。当敌人和角色面对面零距离贴死（站在挥刀圆弧的内侧）时，角色挥刀，**刀尖是从敌人后背外侧绕过去的**，刀尖根本没碰到敌人，真正砍过敌人胸口的是刀柄到刀尖中间的**刀身**。如果只查刀尖，贴脸反而砍不中人；加上这个从刀柄连到刀尖的胶囊体，整段刀身碰到的敌人都会被收进来。

```text
【查询 3：OverlapCapsuleNonAlloc（从刀柄到刀尖包住整把刀身的胶囊体）】
      ╭───────────────────────────────────────────────╮
      │  (刀柄 hilt) ═════════════════════ (刀尖 tip)  │  ← 半径 shaftRadius (0.3m) 的刀身胶囊
      ╰───────────────────────────────────────────────╯
      （敌人贴身站在挥砍圆弧内侧时，刀尖从外侧划过，靠这个刀身胶囊检测命中）
```

### 3. LateUpdate 与 FillOverlapping 源码
对照上面的调用树和三种形状，看 `Hitbox.cs` 中的真实代码：

```csharp
// Hitbox.cs
// 动画在 Update 写骨头，受击胶囊在物理步进才同步。LateUpdate 里先 Sync 再扫。
private void LateUpdate()
{
    if (!isActive) return;

    // 动画在 Update 刚改过骨骼 Transform，先強制同步到物理引擎，否则查到的是旧位置
    Physics.SyncTransforms();

    Vector3 currentPos = transform.position;
    Vector3 delta = currentPos - lastCastPos;
    float distance = delta.magnitude;

    // 【查询 1】武器有位移 → 从上一帧刀尖扫到本帧刀尖，拉出球形管道防高速挥砍穿透
    if (distance > 0.0001f)
    {
        Vector3 direction = delta / distance;
        RaycastHit[] hits = Physics.SphereCastAll(
            lastCastPos, castRadius, direction, distance, targetLayers,
            QueryTriggerInteraction.Collide);
        // 把管道扫到的所有碰撞体交给 ProcessHits → ProcessCollider 处理
        ProcessHits(hits);
    }

    // 【查询 2 + 查询 3】每帧原地重叠点检，结果汇总进 overlappingThisFrame 集合
    overlappingThisFrame.Clear();
    FillOverlapping(overlappingThisFrame);
    foreach (CharacterBody target in overlappingThisFrame)
    {
        // 把重叠查到的角色交给 TryHit 去重并上报
        TryHit(target, currentPos);
    }

    blockedUntilExit.RemoveWhere(body => !overlappingThisFrame.Contains(body));

    // 记录本帧刀尖位置，作为下一帧查询 1 的起点
    lastCastPos = currentPos;
}

private void FillOverlapping(HashSet<CharacterBody> dest)
{
    // 【查询 2】在当前刀尖位置原地放一个半径 castRadius 的球，防起点已嵌在敌人身体里漏检
    AddOverlapping(dest, Physics.OverlapSphereNonAlloc(
        transform.position, castRadius, overlapBuf, targetLayers,
        QueryTriggerInteraction.Collide));

    // 【查询 3】从刀柄 (hilt) 到刀尖 (tip) 包一个半径 shaftRadius 的胶囊体，覆盖整段刀身
    // 贴身站在挥砍内侧时，刀尖会从身侧刮过，必须连柄到尖一起扫
    Vector3 tip = transform.position;
    Vector3 hilt = transform.parent != null ? transform.parent.position : tip;
    float shaft = Mathf.Max(castRadius, shaftRadius);
    if ((tip - hilt).sqrMagnitude > 0.0001f)
    {
        AddOverlapping(dest, Physics.OverlapCapsuleNonAlloc(
            hilt, tip, shaft, overlapBuf, targetLayers,
            QueryTriggerInteraction.Collide));
    }
}

// 供 FillOverlapping 调用：从 overlapBuf 缓冲数组里提取 Hurtbox 所属的敌人放入 dest 集合
private void AddOverlapping(HashSet<CharacterBody> dest, int count)
{
    for (int i = 0; i < count; i++)
    {
        Collider col = overlapBuf[i];
        if (col == null) continue;
        Hurtbox hurtbox = col.GetComponentInParent<Hurtbox>();
        if (hurtbox != null && hurtbox.Owner != null && hurtbox.Owner != owner)
            dest.Add(hurtbox.Owner);
    }
}
```

注意这里的一个细节：`OverlapSphereNonAlloc` 和 `OverlapCapsuleNonAlloc` 都把查到的碰撞体写进预分配好的固定数组 `overlapBuf`（长度 16）并返回命中个数 `count`，再由 `AddOverlapping` 遍历前 `count` 个元素提取 `hurtbox.Owner`，不会在每帧产生数组分配。

## 3. 区分命中与拼刀，以及单段去重

### 1. ProcessHits 与 ProcessCollider：从扫掠结果分流
回到第 2.1 节的调用树：
- **查询 1（`SphereCastAll`）** 扫出 `RaycastHit[] hits` 后，调用 `ProcessHits(hits)`，里面逐个调用 `ProcessCollider(col, hitPoint)`：
  - 如果撞到的是别人的身体（`Hurtbox`），调用 `TryHit(hurtbox.Owner, hitPoint)`；
  - 如果撞到的是别人的武器（`Hitbox`），调用 `TryClash(other, hitPoint)` 处理双方武器相撞（拼刀）。
- **查询 2 和查询 3（`FillOverlapping`）** 通过 `AddOverlapping` 提取出 `Hurtbox.Owner` 后，在 `LateUpdate` 的 `foreach` 循环里直接调用 `TryHit(target, currentPos)`。

完整源码如下：

```csharp
// Hitbox.cs
// 由 LateUpdate 的查询 1 (SphereCastAll) 调用
private void ProcessHits(RaycastHit[] hits)
{
    for (int i = 0; i < hits.Length; i++)
    {
        if (hits[i].collider == null) continue;
        ProcessCollider(hits[i].collider, hits[i].point);
    }
}

// 由 ProcessHits 调用：区分扫到的是对方的身体 (Hurtbox) 还是对方的武器 (Hitbox)
private void ProcessCollider(Collider col, Vector3 hitPoint)
{
    Hurtbox hurtbox = col.GetComponentInParent<Hurtbox>();
    if (hurtbox != null && hurtbox.Owner != owner)
    {
        TryHit(hurtbox.Owner, hitPoint);
        return;
    }

    Hitbox other = col.GetComponentInParent<Hitbox>();
    if (other != null && other != this && other.Owner != owner)
        TryClash(other, hitPoint);
}

// 扫到对方武器 Hitbox 时调用：处理拼刀去重与单方上报
private void TryClash(Hitbox other, Vector3 hitPoint)
{
    if (other == null || other.Owner == owner) return;
    if (!clashedPartners.Add(other)) return;
    // 双方 Hitbox 都会扫到对方；只让 InstanceID 较小的一方上报，避免一帧内架势双倍结算
    if (GetInstanceID() > other.GetInstanceID()) return;
    CombatManager.Instance.ReportClash(this, other, hitPoint);
}

// 扫到对方身体 Hurtbox 时调用（查询 1 的 ProcessCollider 和查询 2/3 的 foreach 都会汇聚到这里）
private void TryHit(CharacterBody target, Vector3 hitPoint)
{
    if (target == null || target == owner) return;
    if (blockedUntilExit.Contains(target)) return;
    if (!hitTargets.Add(target)) return;

    Hurtbox hurtbox = target.GetComponentInChildren<Hurtbox>();
    CombatManager.Instance.ReportHit(this, hurtbox, hitPoint);
}
```

### 2. 为什么要做这两处去重？

#### (1) 角色命中去重：`hitTargets`
一次挥刀的脉冲窗口（比如 `atk1` 的 `0.23s ~ 0.50s`）会持续约 16 帧。在这 16 帧里，每一帧 `LateUpdate` 的三种几何查询都会扫到站在面前的同一个敌人，并调用 `TryHit`。

`TryHit` 里的 `if (!hitTargets.Add(target)) return;` 利用 `HashSet.Add` 的返回值：
- 第 1 次扫到该敌人时，集合里还没有他，`Add` 返回 `true`，继续向下调用 `CombatManager.Instance.ReportHit` 结算这一刀；
- 同一脉冲后续帧再扫到他时，`Add` 返回 `false`，直接 `return`，保证一刀只结算一次。

**什么时候清空 `hitTargets`？**
在 `SetConfig`、`Enable`、`Disable` 中都会调用 `hitTargets.Clear()`。因此：
- 单段攻击里，脉冲持续期间不重开 Hitbox（见 `03` 的 `ApplyHitbox`），集合一直保留；
- 多段连斩招式（一个 `AttackConfig` 里配了多个 `hitPulses`）在从脉冲 0 切到脉冲 1 时，`ApplyHitbox` 会先 `DisableWeaponHit` 再 `EnableWeaponHit`，`hitTargets` 被清空，第二刀就能正常再次命中同一个敌人。

#### (2) 拼刀去重：`clashedPartners` + `GetInstanceID()`
当玩家和 Boss 同时挥刀、两把武器的 `Hitbox` 都处于开启状态并撞在一起时，会出现两个重复问题：
1. **多帧持续相交**：两把刀在几帧内一直重叠。`clashedPartners.Add(other)` 保证在当前脉冲窗口内，对同一把对方武器只处理一次；
2. **同一帧双方互扫**：在同一帧里，玩家的刀扫到了 Boss 的刀（调一次 `TryClash`），Boss 的刀也扫到了玩家的刀（又调一次 `TryClash`）。如果不加限制，一次拼刀会调用两次 `ReportClash`，双方涨双倍架势。所以代码加了 `if (GetInstanceID() > other.GetInstanceID()) return;`，约定永远只让 Unity 对象 `InstanceID` 较小的那把刀上报，另一把刀直接忽略。

到这里，`Hitbox` 完成了物理检测与去重，通过 `CombatManager.Instance.ReportHit(this, hurtbox, hitPoint)`（或 `ReportClash`）把结果交出去。接下来的转发、防御四路裁决与扣血涨架势，见下一篇（`05-伤害判定与防御裁决`）。
