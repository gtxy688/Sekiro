## 1. 从命中上报到防守方总入口：CombatManager → CombatResolver → ReceiveHit

### 1. 上报与转发的完整调用树
上一篇（`04-命中检测与去重`）讲到，`Hitbox` 几何扫掠击中对方身体 `Hurtbox` 并通过去重后，调用 `CombatManager.Instance.ReportHit`。

从这里开始，命中进入裁决与伤害结算链路，完整调用关系如下：

```text
Hitbox.TryHit(target, hitPoint)
  └─ CombatManager.ReportHit(hitbox, hurtbox, hitPoint)
       ├─ CombatResolver.ReportHit(hitbox, hurtbox, hitPoint)
       │    └─ target.ReceiveHit(attacker, BaseDamage, PostureDamage, ...)   进入防守方总入口
       │         ├─ 1. 演出锁与战败检查 (IsFinisherLocked || IsDefeated)
       │         ├─ 2. 组装 HitData 结构体快照
       │         ├─ 3. TryPassiveDeflect(hit)                    Boss 被动防御先拦截
       │         ├─ 4. MainStateMachine.CurrentState.OnHitReceived(hit)      防守方当前状态链拦截
       │         └─ 5. 若上面都未拦截（返回 false，即肉身受击）：
       │              ├─ TakeDamage(healthDmg, postureDmg, attacker)         扣血 + 涨架势
       │              ├─ NotifyDeflectHitFailed()                            结束未成功的弹反尝试（记 1 次空按）
       │              └─ EnterStunned(...)                                   切入顶层受击状态 StunnedState
       └─ TimeScaleController.HitStop()                          触发顿帧
```

---

### 2. CombatManager 与 CombatResolver 转发源码
`CombatManager` 收到 `Hitbox` 的上报后，一方面转交给 `CombatResolver`，另一方面直接调用 `TimeScaleController.HitStop()` 触发全局顿帧：

```csharp
// CombatManager.cs
// A 的武器扫到 B 的 Hurtbox
public void ReportHit(Hitbox hitbox, Hurtbox hurtbox, Vector3 hitPoint)
{
    resolver.ReportHit(hitbox, hurtbox, hitPoint);
    TimeScaleController.HitStop();
}
```

`CombatResolver` 从 `hitbox.Config`（即当前脉冲锁存的 `AttackConfig`）读取基础伤害、架势伤害、危字类型、击退和受击等级，调用防守方 `target.ReceiveHit`：

```csharp
// CombatResolver.cs
// A 的武器扫到 B 的 Hurtbox
public void ReportHit(Hitbox hitbox, Hurtbox hurtbox, Vector3 hitPoint)
{
    CharacterBody attacker = hitbox.Owner;
    CharacterBody target = hurtbox.Owner;

    // 排除打到自己（双保险，Hitbox 侧已过滤）
    if (attacker == null || target == null || attacker == target) return;

    // 近战伤害与受击参数读当前 AttackConfig，防御和扣血由目标 ReceiveHit 继续处理。
    target.ReceiveHit(attacker, hitbox.Config.BaseDamage, hitbox.Config.PostureDamage, hitPoint,
                      hitbox.Config.Perilous != PerilousType.None, hitbox.Config.Perilous,
                      hitbox.Config.Knockback, hitbox.Config.HitGrade, false);
}
```

### 3. 防守方总入口：CharacterBody.ReceiveHit 源码
`ReceiveHit` 是玩家与 Boss 共用的受击入口，执行在**受击者自己的 `CharacterBody`** 上。排除忍杀演出锁与已战败的情况后，它把零散参数打包成一个 `HitData` 结构体，再按顺序交给两个入口处理：

1. **受击者自身的被动防御（`TryPassiveDeflect`）**：先检查本角色的 `EnablePassiveDeflect` 开关。当前玩家预制体关闭此能力，因此玩家受击时也会调用这个方法，但会立即返回 `false`；Boss 由 `BTBrain.Start` 根据 `DisablePassiveDeflect` 设置是否启用，再按自身状态尝试自动防御。
2. **受击者当前的状态（`MainStateMachine.CurrentState.OnHitReceived(hit)`）**：被动防御未接手时，继续由本角色的当前状态判断防御、闪避无敌或二次受击等处理。

例如 Boss 砍中玩家时，`this` 和 `DeflectMemory` 保存的 `body` 都指向玩家，`hit.attacker` 才指向 Boss；被动防御入口读取的是玩家自己的开关。

任一入口返回 `true`，都表示这次命中已被接手处理，`ReceiveHit` 直接返回，避免再执行下方的普通伤害与受击硬直逻辑。**已处理不等于完全无伤**：格挡可能增加架势，二次受击分支也可能已经扣血。只有两个入口都未处理时，才继续向下结算：

```csharp
// CharacterBody.cs
// 接收近战或箭矢上报，先由防御与当前状态拦截，再结算伤害和强制受击状态。
public void ReceiveHit(CharacterBody attacker, int healthDmg, float postureDmg, Vector3 hitPoint,
                       bool isPerilous = false, PerilousType perilousType = PerilousType.None,
                       float knockback = 0f,
                       HitGrade hitGrade = HitGrade.Light,
                       bool isProjectile = false)
{
    // 1. 忍杀演出锁或已战败期间忽略命中
    if (IsFinisherLocked || IsDefeated) return;

    // 2. HitData 是本次命中的数据快照，攻方传来的伤害、类型等信息随它交给防守状态。
    HitData hit = new HitData
    {
        attacker = attacker,
        healthDmg = healthDmg,
        postureDmg = postureDmg,
        hitPoint = hitPoint,
        isPerilous = isPerilous,           // 危字攻击标记
        perilousType = perilousType,
        knockback = knockback,             // 受击表现接口：击退强度
        hitGrade = hitGrade,
        isProjectile = isProjectile
    };

    bool alreadyBroken = IsPostureBroken;

    // 3. 被动防御先于当前状态拦截，让可防御的 Boss 当场转入格挡反应。
    if (TryPassiveDeflect(hit)) return;

    // 4. 父状态先拦截，再逐层转交当前叶子处理防御、无敌或二次受击。
    // 返回 true 代表命中已处理，可能已经加过架势；不是统一表示“完全没有受到影响”。
    if (MainStateMachine.CurrentState != null &&
        MainStateMachine.CurrentState.OnHitReceived(hit))
    {
        return; // 被状态拦截了（盾反成功 / 垫步无敌 / 识破 / 二次受击）
    }

    // 5. 没拦住 → 伤害/架势结算：扣血 + 涨架势 + 死亡判定
    TakeDamage(healthDmg, postureDmg, attacker);

    // 实际受伤后结束未成功的防御尝试；致死已按生命周期取消，避免重复记空按。
    if (CurrentHP > 0)
        NotifyDeflectHitFailed();

    // 玩家挨实锤打断 Boss 连弹计数，下次要重新弹满 2 次才可能 JumpThrust。
    if (HitReactionUtil.IsPlayer(this) && attacker != null)
        attacker.ResetConsecutiveTimesParried();

    // TakeDamage 的死亡回调已切换状态，不能继续用普通受击把死亡状态盖掉。
    if (CurrentHP <= 0) return;

    if (hit.isPerilous && hit.perilousType == PerilousType.Grab
        && HitReactionUtil.IsPlayer(this)
        && CombatManager.Instance.TryStartGrabThrow(attacker, this))
        return;

    HurtContext ctx = knockback > 0f ? HurtContext.Heavy : HurtContext.Normal;

    // 玩家已经倒地后再挨刀：解除崩解，切 Hurt_Heavy 倒地受击。
    // Boss 崩解是处决窗口，保持倒地，不能被普通命中抬起来。
    if (alreadyBroken)
    {
        if (HitReactionUtil.IsPlayer(this))
        {
            ClearPostureBreak();
            EnterStunned(HitGrade.Heavy, "hit: player knocked down follow-up");
        }
        return;
    }

    // 本次命中才刚打崩：TakeDamage 已切 StaggerBroken，不要覆盖成普通受击
    if (IsPostureBroken) return;

    // 危字 / 飞舟：结算伤害但不切受击，招继续
    if (AttackUninterruptible)
        return;

    // 6. 强制打断当前行为，切入受击父状态。玩家按招式等级，Boss 仍按击退。
    if (HitReactionUtil.IsPlayer(this))
        EnterStunned(hit.hitGrade);
    else
        EnterStunned(ctx);
}
```

### 4. Boss 被动防御：TryPassiveDeflect 怎样当场切入防御
**被动防御是受击时自动尝试格挡的能力**：Boss 无需提前收到防御指令，在防御条件允许时，命中入口会当场请求格挡；连续普通格挡达到配置阈值后，下一次符合条件的命中会升级为完美弹反。玩家的主动防御则通过防御输入进入 `DeflectState`，再由当前状态裁决命中。

能力是否启用由受击者自己的 `EnablePassiveDeflect` 决定。该字段默认是 `false`，当前玩家预制体也保存为关闭；Boss 的 `BTBrain.Start` 在依赖检查通过后执行以下赋值，调试开关未禁用时开启被动防御：

```csharp
body.EnablePassiveDeflect = !DisablePassiveDeflect;
```

因此，玩家与 Boss 都经过 `TryPassiveDeflect`，但当前只有开启能力的角色才会继续执行防御判断。**方法本身没有额外判断角色是不是 Boss**；如果误把玩家的开关打开，玩家也可能获得自动防御能力。

它的完整调用链是：

```text
CharacterBody.ReceiveHit(hit)
  └─ CharacterBody.TryPassiveDeflect(hit)
      └─ DeflectMemory.TryPassiveDeflect(hit)
          ├─ 检查受击者自己的 EnablePassiveDeflect 与 IsDefeated
          │    └─ 未启用或已战败 → return false，交回 ReceiveHit 后续流程
          ├─ 排除危字攻击、攻击方缺失、正在攻击、被弹硬直与架势崩解
          ├─ 按连挡计数 passiveDeflectCount 决定模式：
          │    ├─ 未达阈值 threshold → DeflectEntryMode.PassiveGuard（普通格挡）
          │    └─ 已达阈值 threshold → DeflectEntryMode.PerfectParry（升级为完美弹反）
          └─ 调用构造时注入的委托 enterDeflectState(hit, mode)：
               └─ CharacterBody.TryChangeGroundedSubState(g => new DeflectState(..., mode, pendingHit: hit))
                    └─ DeflectState.OnEnter()
                         └─ 当场结算传入的 pendingHit.Value（调 HandlePerfectParry 或 HandleGuardHit）
```

看 `CharacterBody` 注入委托与 `DeflectMemory.TryPassiveDeflect` 的源码：

```csharp
// CharacterBody.cs
// DeflectMemory 记录 Boss 被动防御和连续被弹次数，通过委托请求本角色切入防御。
private DeflectMemory deflect;
private DeflectMemory Deflect => deflect ??= new DeflectMemory(this,
    (hit, mode) => TryChangeGroundedSubState(g => new DeflectState(this, g,
        remash: false, mode: mode, pendingHit: hit)));

public bool EnablePassiveDeflect;

public bool TryPassiveDeflect(HitData hit) => Deflect.TryPassiveDeflect(hit);
```

```csharp
// DeflectMemory.cs
// 可防御时按连续格挡次数选择普通格挡或完美弹反，并当场处理命中。
public bool TryPassiveDeflect(HitData hit)
{
    if (!body.EnablePassiveDeflect || body.IsDefeated) return false;
    if (hit.isPerilous || hit.attacker == null) return false;
    // 攻击中（可被抓前摇）/ 被弹硬直 / 崩解中 → 不回防御，走常规受击
    if (body.IsAttacking || body.IsParried || body.IsPostureBroken) return false;

    float now = Time.time;
    CharacterConfig config = body.Config;
    int threshold = config.PassiveDeflectThreshold;
    float resetWindow = config.PassiveDeflectResetWindow;
    if (passiveDeflectCount > 0 && now - lastPassiveDeflectTime > resetWindow)
        passiveDeflectCount = 0;
    lastPassiveDeflectTime = now;

    bool upgraded = passiveDeflectCount >= threshold;
    // 先看此前已累计次数，再决定这次是否升级；普通格挡达到阈值后的下一次才完美弹反。
    passiveDeflectCount = upgraded ? 0 : passiveDeflectCount + 1;

    DeflectEntryMode mode = upgraded ? DeflectEntryMode.PerfectParry : DeflectEntryMode.PassiveGuard;
    return enterDeflectState(hit, mode);
}
```

当 `enterDeflectState` 把地面子状态切成 `DeflectState` 时，`ChangeState` 立即调用 `DeflectState.OnEnter()`，在 `OnEnter` 里面当场把 `pendingHit` 结算掉：

```csharp
// DeflectState.cs OnEnter（被动防御分支）
// 被动入口直接结算传入的命中，再短暂保持防御姿态，不开主动尝试。
if (mode != DeflectEntryMode.Normal)
{
    if (pendingHit.HasValue)
    {
        if (mode == DeflectEntryMode.PerfectParry)
            HandlePerfectParry(pendingHit.Value);
        else
            HandleGuardHit(pendingHit.Value);
    }
    PlayGuardLoop(force: true);
    return;
}
```

## 2. 防御状态机的四路裁决（OnHitReceived）

### 1. OnHitReceived 下传与四路分流调用树
如果 `TryPassiveDeflect` 返回 `false`（比如玩家未启用被动防御，或者 Boss 正在出招），`ReceiveHit` 进入第 4 步：调用受击者自己的 `MainStateMachine.CurrentState.OnHitReceived(hit)`。

先看清 `OnHitReceived` 从顶层状态机一路传到具体子状态的完整调用树：

```text
CharacterBody.ReceiveHit(hit)
  └─ MainStateMachine.CurrentState.OnHitReceived(hit)
      │
      ├─ 【情况 A：顶层已经是 StunnedState（角色正在受击硬直中又挨了一刀）】
      │    └─ StunnedState.OnHitReceived(hit)                      （继承 HierarchicalState）
      │         └─ StunnedState.OnParentHandleHit(hit)             父层直接拦截：
      │              ├─ body.TakeDamage(hit.healthDmg, hit.postureDmg)
      │              ├─ GroundStunnedState.ReceiveFollowUpHit(hit) 刷新受击动画与计时
      │              └─ return true                                已处理，ReceiveHit 直接结束
      │
      └─ 【情况 B：顶层是 GroundedState（角色在地面状态，继承 HierarchicalState，未重写 OnHitReceived）】
           ├─ GroundedState.OnParentHandleHit(hit)                 未重写，默认 return false（父层不拦截）
           └─ SubStateMachine.CurrentState.OnHitReceived(hit)      转交当前地面子状态裁决：
                │
                ├─ 路线 1：当前子状态是 DodgeState（垫步闪避）
                │    └─ DodgeState.OnHitReceived(hit)
                │         ├─ 无方向垫步 + 危字突刺 → ChangeState(new MikiriCounterState) → return true
                │         ├─ dodgeTimer <= iFrameDuration（无敌帧内）                   → return true
                │         └─ 已过无敌帧                                                 → return false
                │
                ├─ 路线 2 & 3：当前子状态是 DeflectState（举刀防御）
                │    └─ DeflectState.OnHitReceived(hit)
                │         ├─ body.AdvanceDeflectAttempt()          先按当前时间推进弹反窗口到期检查
                │         ├─ inParryWindow = IsParryWindowActive() 调 DeflectAttemptTracker.CanParry 查窗口
                │         ├─ 路线 2（inParryWindow == true） → HandlePerfectParry(hit) → return true
                │         └─ 路线 3（inParryWindow == false）→ HandleGuardHit(hit)     → return true（危字除外）
                │
                └─ 路线 4：当前子状态是 IdleState / MoveState / AttackState 等（无防御状态）
                     └─ 未重写 OnHitReceived，直接执行基类 BaseState.OnHitReceived(hit)
                          └─ 默认 return false → 回到 ReceiveHit 第 5 步：TakeDamage 扣血 + EnterStunned 切受击
```

基类 `BaseState` 和父状态基类 `HierarchicalState` 的转发源码如下：

```csharp
// BaseState.cs
// true 表示状态已处理本次命中，上层不再重复结算；false 交由角色统一扣血并切入受击。
public virtual bool OnHitReceived(HitData hit)
{
    return false;
}
```

```csharp
// HierarchicalState.cs
// 父层先处理统一受击规则，未拦截时继续转交叶子的防御或无敌判定。
public override bool OnHitReceived(HitData hit)
{
    // 先应用父状态的受击规则。
    if (OnParentHandleHit(hit))
    {
        return true;
    }

    // 未拦截时交给当前子状态。
    if (SubStateMachine.CurrentState != null)
    {
        return SubStateMachine.CurrentState.OnHitReceived(hit);
    }

    return false;
}
```

下面顺着调用树的 **路线 1 ～ 路线 4** 逐一看具体状态里的实现。

---

### 2. 路线 1：处于 DodgeState（识破突刺与闪避无敌帧）
`DodgeState` 直接继承 `BaseState`，重写了 `OnHitReceived`：

```csharp
// DodgeState.cs
public override void OnEnter()
{
    ...
    dodgeTimer = 0f;
    // 进垫步当下有没有方向键：识破只认无方向，不看垫步动画叫前还是后
    mikiriEligible = body.MoveDirection.sqrMagnitude < 0.01f;
    ...
}

// 无方向垫步可识破危字突刺；带方向垫步只按无敌时长拦截命中。
public override bool OnHitReceived(HitData hit)
{
    // 1. 识破判定：起手未推方向键 + 对方是危字突刺 (PerilousType.Thrust)
    if (mikiriEligible && hit.isPerilous && hit.perilousType == PerilousType.Thrust)
    {
        parent.SubStateMachine.ChangeState(new MikiriCounterState(body, parent, hit));
        return true;
    }

    // 2. 无敌帧判定：垫步经过时间 dodgeTimer 在配置的 DodgeIFrame（如 0.25s）之内
    if (dodgeTimer <= iFrameDuration)
    {
        // true 让 CharacterBody 跳过这次普通伤害结算；超出无敌时间则回到正常受击链。
        return true;
    }
    return false;
}
```

- **看破（识破）**：如果玩家按下垫步瞬间没有推摇杆（`mikiriEligible == true`，默认向前垫步），且扫过来的这一击是危字突刺（`PerilousType.Thrust`），直接把地面子状态切到 `MikiriCounterState`（踩刀反制，打断 Boss 并大幅涨 Boss 架势），返回 `true`；
- **无敌帧免伤**：普通垫步在 `dodgeTimer <= iFrameDuration` 期间被扫中时直接返回 `true`，`ReceiveHit` 收到 `true` 后直接 `return`，玩家不扣血、不涨架势、动作也不被打断；如果垫步后半段已经过了 `iFrameDuration`，返回 `false`，回到 `ReceiveHit` 挨打。

### 3. 路线 2 与路线 3：处于 DeflectState（完美弹反与普通格挡）

#### (1) DeflectState.OnHitReceived 入口分流
当角色正在 `DeflectState`（举刀防御状态，继承 `BaseState`）时，命中进入 `DeflectState.OnHitReceived`：

```csharp
// DeflectState.cs
public override bool OnHitReceived(HitData hit)
{
    // CharacterBody.ReceiveHit 先问当前状态；这里处理成功后返回 true，阻止重复走普通扣血受击。
    // 命中入口先推进到期：同帧的输入接受与命中按真实执行顺序处理，不回滚、不开事后窗口。
    body.AdvanceDeflectAttempt();
    if (canceling) return false;

    bool inParryWindow = IsParryWindowActive();

    // 危字：普通格挡等于没防。突刺/抓取只有弹反窗口内能弹开。横扫已当普通刀，走下面格挡/弹反。
    if (hit.isPerilous)
    {
        if (inParryWindow) return HandlePerfectParry(hit);
        return false;
    }

    if (inParryWindow) return HandlePerfectParry(hit);

    // 窗口外（或本次防御没有主动窗口）：普通格挡。
    // 普通格挡不给已经结束的尝试追加失败，也不清罚。
    return HandleGuardHit(hit);
}

// 唯一的弹反资格：Tracker 里未结束的尝试 + 固定半开窗口。
private bool IsParryWindowActive()
{
    return attemptId != 0 && body.IsDeflectParryActive(attemptId);
}
```

这里的分流只看一件事：`IsParryWindowActive()` 为 `true` 还是 `false`：
- 若为 `true`（处于完美弹反时间窗内）：调用 `HandlePerfectParry(hit)`（路线 2）；
- 若为 `false`（已经过了弹反窗，只是按住防御键举刀，或系统自动回防）：危字攻击返回 `false` 破防挨打，普通攻击调用 `HandleGuardHit(hit)`（路线 3）。

#### (2) IsParryWindowActive 的调用链：DeflectAttemptTracker 怎样算窗口与缩窗惩罚
`DeflectState` 里的 `attemptId` 和 `IsParryWindowActive()` 都是通过 `CharacterBody` 调用 `DeflectAttemptTracker` 管理的，它的生命周期调用链如下：

```text
1. 按键按下时：PlayerBrain.OnDeflectStarted
     └─ body.BeginDeflectPress() → DeflectAttemptTracker.BeginPress()
          └─ 生成自增的按键身份 pressId，放进 DeflectCommand(pressId)

2. 进入防御状态时：DeflectState.OnEnter()
     └─ attemptId = body.BeginDeflectAttempt(pressId) → DeflectAttemptTracker.BeginAttempt(pressId, Time.time, settings)
          ├─ 结算上一次未完成的尝试（记 1 次空按 emptyCount++）
          ├─ 若距上次开启超过 EmptyResetInterval（如 0.5s），emptyCount 清零
          ├─ ComputeWindow(emptyCount, settings) 计算本次窗口长度 activeWindow
          └─ 记录本次窗口半开区间：[activeStartTime = now, activeDeadline = now + activeWindow)

3. 命中判定时：DeflectState.OnHitReceived(hit)
     ├─ body.AdvanceDeflectAttempt() → DeflectAttemptTracker.Advance(Time.time)
     │    └─ 若 now >= activeDeadline，提前以 Expired 结束尝试（emptyCount++）
     └─ IsParryWindowActive() → body.IsDeflectParryActive(attemptId) → DeflectAttemptTracker.CanParry(attemptId, Time.time)
          └─ 判断 activeStartTime <= now && now < activeDeadline
```

`DeflectAttemptTracker` 的核心源码：

```csharp
// DeflectAttemptTracker.cs（节选）
// 开启主动尝试并返回 ID；系统回防、重复按下或复位残留返回 0。
public int BeginAttempt(int pressId, float now, Settings settings)
{
    if (pressId <= 0 || pressId <= lastAttemptedPressId || pressId < attemptedFloor)
        return 0;

    Settings s = settings.Normalized(out _);

    // 1. 旧尝试：还没到期就是被新按下替换，已经到期就是自然到期 —— 两者都只记一次空按。
    EndActiveAttempt(now < activeDeadline
        ? DeflectAttemptEndReason.Replaced
        : DeflectAttemptEndReason.Expired);

    // 2. 恢复：相邻两次实际开启尝试的间隔超过 EmptyResetInterval 则清零空按计数
    bool reset = lastBeginTime > 0f && now - lastBeginTime > s.EmptyResetInterval;
    if (reset) emptyCount = 0;

    // 3. 新窗口按当前空按次数计算：penaltySteps = max(0, emptyCount - grace)
    float window = ComputeWindow(emptyCount, s);
    int attemptId = nextAttemptId++;

    activeAttemptId = attemptId;
    activePressId = pressId;
    activeStartTime = now;
    activeWindow = window;
    activeDeadline = now + window;
    activeSucceeded = false;
    lastAttemptedPressId = pressId;
    lastBeginTime = now;

    return attemptId;
}

// 下一次窗口：max(最小窗口, 基础窗口 × 惩罚系数^超出宽容次数)。
public static float ComputeWindow(int emptyCount, Settings settings)
{
    Settings s = settings.Normalized(out _);
    int penaltySteps = emptyCount - s.EmptyGraceCount;
    if (penaltySteps <= 0) return s.Window;

    float window = s.Window * Mathf.Pow(s.EmptyPenalty, penaltySteps);
    return window < s.WindowMin ? s.WindowMin : window;
}

// 资格只看当前尝试的半开区间 [start, deadline)，截止时刻不算成功，抬刀动画不延长窗口。
public bool CanParry(int attemptId, float now)
{
    if (attemptId <= 0 || attemptId != activeAttemptId) return false;
    return activeStartTime <= now && now < activeDeadline;
}

// 成功记账：只有当前有效尝试能清罚
public bool RecordSuccess(int attemptId, float now)
{
    if (!CanParry(attemptId, now)) return false;
    if (activeSucceeded) return false;

    activeSucceeded = true;
    emptyCount = 0;
    return true;
}
```

这样就实现了《只狼》里的防抖刀机制：正常单次点按拿满完整窗口 `Window`；如果玩家因为害怕一直狂按防御键（每次都没弹中刀就重按或到期），`emptyCount` 不断累加，超出宽容次数 `EmptyGraceCount` 后，窗口按指数 `Window * EmptyPenalty^penaltySteps` 缩小到 `WindowMin`；一旦真正弹中一次，`RecordSuccess` 把 `emptyCount` 清零，窗口立刻恢复。

#### (3) 路线 2 执行：HandlePerfectParry（完美弹反）
当 `inParryWindow == true` 时，`DeflectState.OnHitReceived` 调用 `HandlePerfectParry(hit)`，它的内部调用链如下：

```text
DeflectState.HandlePerfectParry(hit)
  ├─ 1. body.RecordDeflectSuccess(attemptId)                     清空连续空按惩罚 emptyCount = 0
  ├─ 2. 对攻击方结算（近战非飞行物）：
  │      ├─ hit.attacker.AccumulatePosture(DeflectPostureGain, allowBreak: true, PostureBreakSource.Deflect)
  │      └─ 若未打崩、非霸体且是本招末刀 (AttackStateBase.IsLastHit)：
  │           └─ hit.attacker.ForceParryStun(armKengeki: false)  打断攻击方，切入 ParriedState 弹刀硬直
  ├─ 3. 回合权与连弹计数更新：
  │      ├─ 若防守方是 Boss → body.KengekiArmed = true           允许 Boss 行为树安排弹反反击
  │      └─ 若防守方是玩家 → hit.attacker.NotifyPerfectlyParried() 累加 Boss 连续被弹次数
  ├─ 4. 表现与防守方自身计时：
  │      ├─ CombatEventBus.TriggerWeaponDeflected(..., DeflectType.Perfect)
  │      ├─ CombatEventBus.TriggerCameraShake(0.3f)
  │      ├─ TimeScaleController.HitStop()
  │      └─ body.MarkCombatTime()                                防守方自己不涨架势，仅刷新战斗时刻防止回条
  ├─ 5. 若刚打崩了攻击者架势 → ChangeState(new FinisherReadyState)
  └─ 6. 播放弹反动作 (Deflect_Slash 等)，返回 true
```

源码如下：

```csharp
// DeflectState.cs
// 完美弹反：弹开攻击者 + 打铁表现。玩家弹反 Boss 且 Boss 架势崩时给玩家处决确认窗口。
private bool HandlePerfectParry(HitData hit)
{
    // 1. 主动尝试先记成功再切状态，避免特殊反制或崩解切换遗漏清罚。
    if (mode == DeflectEntryMode.Normal)
        body.RecordDeflectSuccess(attemptId);

    if (!hit.isProjectile && hit.attacker != null
        && HitReactionUtil.IsPlayer(body)
        && HitReactionUtil.IsBoatFinalPulseParry(hit.attacker))
    {
        return HandleBoatMutualDeflect(hit);
    }

    bool brokeAttackerPosture = false;
    // 2. 箭不是刀刃相撞：弹开只挡伤害，不涨攻击者架势、不把 Boss 弹进硬直。
    if (hit.attacker != null && !hit.isProjectile)
    {
        float gain = body.Config.DeflectPostureGain;
        brokeAttackerPosture = hit.attacker.AccumulatePosture(
            gain,
            allowBreak: true,
            source: PostureBreakSource.Deflect);
        // 非霸体招只在末刀被弹时打断，保留中间段的连续弹反。
        // 被弹方不武装交锋，避免它刚失去先手就立即反击。
        if (!brokeAttackerPosture && !hit.attacker.AttackUninterruptible
            && AttackStateBase.IsLastHit(hit.attacker))
        {
            hit.attacker.ForceParryStun(armKengeki: false);
            // 预留玩家标准首刀的反击时间，计划存到被弹的 Boss 上；此处不会替玩家自动出刀。
            if (mode == DeflectEntryMode.Normal && HitReactionUtil.IsPlayer(body)
                && !HitReactionUtil.IsPlayer(hit.attacker))
                hit.attacker.ArmPlayerParryAttackWindow(body.LightAttack);
        }
    }

    // 3. 弹反成功方获得优先反击权（回合制）：
    // 只有 Boss 弹反玩家才武装交锋；玩家弹反 Boss 不该给玩家挂 KengekiArmed。
    if (!hit.isProjectile && !HitReactionUtil.IsPlayer(body))
    {
        body.ClearPlayerParryAttackWindow();
        body.KengekiArmed = true;
    }
    // 玩家近战弹开 Boss：累计连续弹开次数，供主动层 JumpThrust（≠ 交锋 3062）。
    if (!hit.isProjectile && HitReactionUtil.IsPlayer(body) && hit.attacker != null)
        hit.attacker.NotifyPerfectlyParried();

    parriedOpponent = hit.attacker;
    float minimumDuration = hit.attacker != null
        ? hit.attacker.Config.ParriedDuration
        : body.Config.ParriedDuration;
    parriedRecoveryTime = Time.time + minimumDuration;

    // 4. 表现与战斗计时：完美弹反防守方自己不涨架势，只调 MarkCombatTime 刷新架势回复延迟
    CombatEventBus.TriggerWeaponDeflected(
        CombatFxPoint.ForDeflect(hit.attacker, body, hit.hitPoint, hit.isProjectile),
        DeflectType.Perfect);
    CombatEventBus.TriggerCameraShake(0.3f);
    TimeScaleController.HitStop();
    body.MarkCombatTime();

    if (HitReactionUtil.IsPlayer(body) && HitReactionUtil.IsArrowHeavyGuard(hit))
        CombatEventBus.TriggerHeavyArrowDefended(body, perfect: true);

    // 5. 主动弹反打崩对手且存在确认动画时进入忍杀准备
    if (brokeAttackerPosture && mode == DeflectEntryMode.Normal &&
        AnimUtil.HasState(body.Animator, "DeflectToFinsher"))
    {
        parent.SubStateMachine.ChangeState(
            new FinisherReadyState(body, parent, hit.attacker));
        return true;
    }

    // 6. 播放完美弹反动画
    inBegin = false;
    currentLoopAnim = null;
    string deflectAnim = HitReactionUtil.IsPlayer(body)
        ? HitReactionUtil.PerfectParryAnim(hit)
        : (hit.knockback > 0f ? "Deflect_HeavySlash" : "Deflect_Slash");
    if (!AnimUtil.HasState(body.Animator, deflectAnim))
    {
        Debug.LogError($"{body.name} 的 Animator 缺少弹反状态：{deflectAnim}");
    }
    else
    {
        AnimUtil.TryCrossFade(body.Animator, deflectAnim, 0.05f);
    }

    if (HitReactionUtil.IsPlayer(body) && HitReactionUtil.IsArrowHeavyGuard(hit))
    {
        guardHurtAnim = deflectAnim;
        waitingGuardHurt = true;
        hasSeenGuardHurt = false;
        arrowHeavyDeflect = true;
        guardFlinchTimer = 0f;
        arrowHeavyLockTimer = 0f;
    }
    else
    {
        guardFlinchTimer = 0.25f;
    }
    return true;
}
```

#### (4) 路线 3 执行：HandleGuardHit（普通格挡）
当 `inParryWindow == false` 时，`DeflectState.OnHitReceived` 调用 `HandleGuardHit(hit)`：

```csharp
// DeflectState.cs
// 窗口外挡住：普通格挡受击（GuardHurt 动画 + 架势上涨，格挡系数削弱架势伤害）
private bool HandleGuardHit(HitData hit)
{
    if (HitReactionUtil.IsPlayer(body))
    {
        // 近战重突刺无法普通格挡，返回 false 交回 ReceiveHit 按破防扣血处理
        if (HitReactionUtil.IsMeleeHeavyPierce(hit))
            return false;
        if (HitReactionUtil.IsArrowHeavyGuard(hit))
            return PlayArrowHeavyGuard(hit);
        // 普通格挡打断「连续弹开」：JumpThrust 只认连弹，不认举盾挨打。
        if (hit.attacker != null && !hit.isProjectile)
            hit.attacker.ResetConsecutiveTimesParried();
    }

    // 防守方自己涨架势（乘上 GuardPostureFactor 格挡系数），不扣 HP
    float posture = hit.postureDmg * body.Config.GuardPostureFactor;
    if (body.AccumulatePosture(posture))
    {
        // 格挡把架势打满已经切崩解，不能再覆盖成 Hurt_Guard。
        return true;
    }

    // 未打满架势：播放格挡受击动画 (Hurt_Guard / Hurt_GuardHeavy)
    inBegin = false;
    currentLoopAnim = null;
    HurtContext guardHurt;
    if (HitReactionUtil.IsPlayer(body))
        guardHurt = HurtContext.Guard;
    else
        guardHurt = hit.knockback > 0f ? HurtContext.GuardHeavy : HurtContext.Guard;
    guardHurtAnim = body.ResolveHurtAnim(guardHurt);
    waitingGuardHurt = true;
    hasSeenGuardHurt = false;
    arrowHeavyGuard = false;
    guardFlinchTimer = 0f;
    AnimUtil.TryCrossFade(body.Animator, guardHurtAnim, 0.03f);

    CombatEventBus.TriggerWeaponDeflected(
        CombatFxPoint.ForDeflect(hit.attacker, body, hit.hitPoint, hit.isProjectile), DeflectType.Normal);
    return true;
}
```

### 4. 路线 4：无防御状态（肉身受击）与四路对比表
当角色处于 `IdleState`、`MoveState`、`AttackState` 等没有重写 `OnHitReceived` 的状态（或者在 `DodgeState` 已过无敌帧、在 `DeflectState` 普通格挡遇到危字攻击）时，`OnHitReceived` 返回 `false`。

执行流回到第 1.3 节 `CharacterBody.ReceiveHit` 的第 5 步：
1. 调用 `TakeDamage(healthDmg, postureDmg, attacker)` 扣减 HP 并全额累加架势；
2. 若存活，调用 `NotifyDeflectHitFailed()` 结束未成功的弹反尝试（计 1 次空按）；
3. 若未致死、未崩解且当前动作无霸体（`!AttackUninterruptible`），调用 `EnterStunned` 将顶层状态机切入 `StunnedState` 播放受击硬直。

四路裁决结果对比：

| 防守方状态与条件 | `OnHitReceived` 返回值 | 防守方 HP | 防守方架势 | 对攻击方的影响 | 防守方后续状态 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **路线 1a**：`DodgeState`（无方向 + 危字突刺） | `true` | 不扣 | 不涨 | 被踩刀打断（`ForceMikiriStun`）并涨架势 | 切 `MikiriCounterState` |
| **路线 1b**：`DodgeState`（`dodgeTimer <= DodgeIFrame`） | `true` | 不扣 | 不涨 | 无 | 留在 `DodgeState` |
| **路线 2**：`DeflectState`（完美弹反窗口内） | `true` | 不扣 | **不涨**（仅调 `MarkCombatTime`） | 涨 `DeflectPostureGain` 架势，末刀切 `ParriedState` | 留在 `DeflectState`（打崩攻方则切 `FinisherReadyState`） |
| **路线 3**：`DeflectState`（窗口外普通格挡） | `true` | 不扣 | 涨 `postureDmg * GuardPostureFactor` | 无 | 留在 `DeflectState` 播 `Hurt_Guard`（满条则切 `StaggerBrokenState`） |
| **路线 4**：`Idle` / `Attack` 等无防御态（或破防） | `false` | 扣 `healthDmg` | 涨 `postureDmg` | 无 | 回到 `ReceiveHit`：切 `StunnedState`（满条切 `StaggerBrokenState`，HP 归零切 `DeadState`） |

## 3. 数值结算与表现广播：CombatStats 与 CombatEventBus

### 1. CombatStats 的调用树
无论是上面哪一条路线，只要涉及扣血、涨架势或自然回架势，最终都会通过 `CharacterBody` 调进 `CombatStats`：

```text
CharacterBody
  ├─ TakeDamage(healthDmg, postureDmg, attacker)                 （由 ReceiveHit 肉身受击调用）
  │    └─ CombatStats.TakeDamage(...)
  │         ├─ CurrentHP -= healthDmg
  │         ├─ AccumulatePosture(postureDmg, allowBreak: true, PostureBreakSource.Attack)
  │         ├─ CombatEventBus.TriggerTakeDamage / TriggerHPChanged
  │         └─ 若 CurrentHP <= 0 → HandleDeath()
  │              └─ 触发 onDeath 回调 → CharacterBody.EnterDead(...) 切入 DeadState
  │
  ├─ AccumulatePosture(amount, allowBreak, source)               （由 TakeDamage / 完美弹反 / 普通格挡 调用）
  │    └─ CombatStats.AccumulatePosture(...)
  │         ├─ CurrentPosture = Min(CurrentPosture + amount, maxPosture)
  │         ├─ MarkCombatTime()                                  刷新 lastHitTime = Time.time
  │         ├─ CombatEventBus.TriggerPostureChanged(...)
  │         └─ 若 allowBreak && CurrentPosture >= maxPosture：
  │              ├─ IsPostureBroken = true
  │              ├─ CombatEventBus.TriggerPostureBroken / TriggerFinisherOpportunityChanged
  │              └─ 触发 onPostureBreak(source) 回调 → CharacterBody.ForcePostureBroken(source)
  │                   └─ 切入 StaggerBrokenState（或 Boss 专属 FinisherVictimState）
  │
  └─ Update() 每帧驱动
       └─ CharacterBody.UpdatePostureDecay()
            └─ CombatStats.UpdatePostureDecay()
                 └─ 当 Time.time - lastHitTime >= PostureDecayDelay 时，每秒减少 CurrentPosture
```

### 2. 扣血、涨架势与自然恢复源码
`CharacterBody` 在构造 `CombatStats` 时，把 `ForcePostureBroken` 和 `EnterDead` 作为回调委托传给 `CombatStats`，让 `CombatStats` 只管算数值，算到满架势或 0 血时通过回调通知 `CharacterBody` 切状态：

```csharp
// CharacterBody.cs
private CombatStats combat;
private CombatStats Combat => combat ??= new CombatStats(
    this,
    source => ForcePostureBroken(source),
    revive => EnterDead(revive, reason: revive ? "death: enter revive pending" : "death: enter game over"));
```

```csharp
// CombatStats.cs
// CharacterBody.ReceiveHit 确认没有被防御/无敌拦截后调用：扣血、加架势，再处理死亡。
public void TakeDamage(int healthDmg, float postureDmg, CharacterBody instigator = null)
{
    if (CurrentHP <= 0) return; // 已死不再重复结算

    GameplaySettings.Load();
    bool skipHp = healthDmg > 0
                  && GameplaySettings.InfiniteHealth
                  && HitReactionUtil.IsPlayer(body);

    if (!skipHp)
        CurrentHP -= healthDmg;
    AccumulatePosture(postureDmg, true, PostureBreakSource.Attack, instigator);

    if (!skipHp)
    {
        // 事件总线：血条/音效/相机都靠这个驱动
        CombatEventBus.TriggerTakeDamage(body, healthDmg, Mathf.Max(CurrentHP, 0));
        CharacterConfig config = body.Config;
        CombatEventBus.TriggerHPChanged(body, Mathf.Max(CurrentHP, 0), config.MaxHP);

        if (CurrentHP <= 0)
            HandleDeath();
    }
}

// 统一累计伤害、格挡或弹反带来的架势，并在达到上限时通知角色崩解。
// allowBreak=false 只累加但不触发崩解；返回 true 仅表示本次确实触发了崩解。
public bool AccumulatePosture(
    float amount,
    bool allowBreak = true,
    PostureBreakSource source = PostureBreakSource.Attack,
    CharacterBody instigator = null)
{
    if (IsPostureBroken) return false; // 崩解中不累计

    CharacterConfig config = body.Config;
    float maxPosture = config.MaxPosture;

    CurrentPosture = Mathf.Min(CurrentPosture + amount, maxPosture);
    MarkCombatTime();

    CombatEventBus.TriggerPostureChanged(body, CurrentPosture, maxPosture);

    if (allowBreak && CurrentPosture >= maxPosture)
    {
        IsPostureBroken = true;
        CurrentPostureBreakSource = source;
        // 崩解 → 崩解硬直（玩家击飞倒地 / Boss 处决窗口）
        CombatEventBus.TriggerPostureBroken(body);
        CombatEventBus.TriggerFinisherOpportunityChanged(body, true);
        onPostureBreak(source);
        return true;
    }

    return false;
}

// 刷新架势回复延迟。完美弹反自己不涨架势，但刀刃相撞仍算战斗，不能开始回条。
public void MarkCombatTime()
{
    lastHitTime = Time.time;
}

// 架势自然回复：停止受击超过 PostureDecayDelay 秒后，每秒回 PostureDecayRate
public void UpdatePostureDecay()
{
    CharacterConfig config = body.Config;
    if (IsPostureBroken || CurrentPosture <= 0f) return;

    if (Time.time - lastHitTime >= config.PostureDecayDelay)
    {
        float rate = config.PostureDecayRate;

        // 格挡姿态使用配置中的回复倍率；是否开始回复仍由受击延迟控制。
        if (body.IsGuarding)
        {
            rate *= config.GuardPostureRecoveryMultiplier;
        }

        // Boss 非线性回复：架势越高回越慢（反函数手感）
        if (config.PostureDecayInverse)
        {
            rate *= 1f - CurrentPosture / config.MaxPosture;
        }

        CurrentPosture = Mathf.Max(0f, CurrentPosture - rate * Time.deltaTime);
        CombatEventBus.TriggerPostureChanged(body, CurrentPosture, config.MaxPosture);
    }
}
```

### 3. 事件总线广播与顿帧的分工
整个攻防裁决过程中，底层逻辑不直接引用 UI 面板或音源组件，表现通知分成两条路：

1. **`CombatEventBus` 静态事件总线**：
   - `TriggerTakeDamage` / `TriggerHPChanged` / `TriggerPostureChanged`：由 `CombatStats` 在数值变化时调用，驱动血条与架势条 UI；
   - `TriggerPostureBroken` / `TriggerFinisherOpportunityChanged`：由 `CombatStats.AccumulatePosture` 在架势打满时调用，驱动崩解音效与忍杀红点 UI；
   - `TriggerWeaponDeflected(point, DeflectType.Normal / Perfect)`：由 `DeflectState`（格挡/完美弹反）调用，驱动打铁火花与铁音；
   - `TriggerCameraShake`：由 `DeflectState.HandlePerfectParry` 和 `CharacterBody.ForcePostureBroken` 调用，驱动相机震屏。
2. **`TimeScaleController.HitStop()` 直接调用**：
   顿帧不走事件总线，在 `CombatManager.ReportHit / ReportProjectileHit` 和 `DeflectState.HandlePerfectParry` 中直接调用 `TimeScaleController.HitStop()` 短暂压低 `Time.timeScale`。
