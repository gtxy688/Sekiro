## 1. 一次攻击从哪里开始

### 1. 指令怎样到达待机状态
上一章讲过，Brain 缓冲池里的 `AttackCommand` 会交给 `CharacterBody.TryExecuteCommand`，再沿 HFSM 逐层下传。攻击指令不在父层被拦截，最终由当前子状态 `IdleState` 处理：

```text
BrainBase.ProcessCommandBuffer()
  └─ CharacterBody.TryExecuteCommand(cmd)
      └─ MainStateMachine.HandleCommand(cmd)
          └─ GroundedState.HandleCommand(cmd)           （继承 HierarchicalState）
              ├─ OnParentHandleCommand(cmd)             父层先问：不处理攻击，返回 false
              └─ SubStateMachine.CurrentState.HandleCommand(cmd)
                  └─ IdleState.HandleCommand(cmd)       待机状态处理攻击指令
                      └─ SubStateMachine.ChangeState(new AttackState(...))
```

```csharp
// IdleState.cs
if (cmd is AttackCommand)
{
    // AttackCommand 只表示“想攻击”，具体哪一招由 CharacterBody 的配置入口提供。
    parent.SubStateMachine.ChangeState(new AttackState(body, parent, body.GetAttackConfig()));
    return true;
}
```

`ChangeState` 退出 `IdleState`、把 `CurrentState` 换成新建的 `AttackState` 并调用它的 `OnEnter()`。从这一刻起，这次攻击的全部逻辑都在 `AttackState` 里完成。

---

### 2. AttackStateBase 与 AttackState 的分工
攻击状态分成两层：

- `AttackStateBase`：所有招式共用的逻辑，包括动画时钟、Hitbox 开关、音效与出箭、窗口校验、退出判断；
- `AttackState`：地面版本，只实现几个与“地面”有关的出口，如攻击结束回哪里、取消成什么、连招派生什么。空中攻击 `AirAttackState` 同样继承基类，实现自己的一套出口。

基类把这些出口声明成虚方法，由子类按环境填写：

```csharp
// AttackState.cs
namespace ARPG.FrameWork.States.Ground
{
    public class AttackState : AttackStateBase
    {
        public AttackState(CharacterBody body, HierarchicalState parent, AttackConfig config)
            : base(body, parent, config)
        {
        }

        // 招式正常结束：回到地面待机
        protected override void ExitToIdle()
        {
            parent.SubStateMachine.ChangeState(new IdleState(body, parent), "attack: finished");
        }

        // 连招：NextCombo 满足条件时，派生下一段地面攻击
        protected override BaseState NewSelf(AttackConfig next)
        {
            return new AttackState(body, parent, next);
        }

        // 取消窗口内按防御：切到弹反/格挡，pressId 原样透传
        protected override bool CancelToDeflect(bool canCancel, DeflectCommand cmd)
        {
            // 不在取消窗口时返回 false，让尚未过期的防御预输入有机会在之后重试。
            if (!canCancel) return false;
            parent.SubStateMachine.ChangeState(
                new DeflectState(body, parent, pressId: cmd.PressId), "attack: cancel to deflect");
            return true;
        }

        // 取消窗口内按闪避：切到垫步
        protected override bool CancelToDodge(bool canCancel)
        {
            if (!canCancel) return false;
            parent.SubStateMachine.ChangeState(new DodgeState(body, parent), "attack: cancel to dodge");
            return true;
        }

        // 后摇段推摇杆：切到移动状态
        protected override bool HandleMoveCommand(MoveCommand moveCmd)
        {
            body.MoveDirection = moveCmd.Direction;
            if (animTime >= config.RecoveryWindowStart &&
                moveCmd.Direction.sqrMagnitude >= 0.01f)
            {
                // 锁定攻击接移动时直接进入四向循环。
                // 若走默认 IdleToWalk，其前向根运动会让角色额外朝目标冲出一段。
                string enterAnim = HasCombatTarget() ? null : "IdleToWalk";
                parent.SubStateMachine.ChangeState(new MoveState(body, parent, enterAnim),
                    "attack: recovery to move");
            }
            return true;
        }
    }
}
```

`AttackState` 没有重写 `OnEnter / OnUpdate / OnExit`，这三个生命周期方法都直接执行 `AttackStateBase` 的实现，后文分别展开。

### 3. 招式配置：AttackConfig
`AttackConfig` 是 ScriptableObject，`IdleState` 通过 `body.GetAttackConfig()` 取得并传给状态。状态本身不写死任何时间和数值，只按配置里的秒数推进。下面是主角第一段轻攻击 `atk1` 的实际配置：

```yaml
AnimName: Attack1             # Animator 里的状态短名
TransitionDuration: 0.1       # 淡入时长
BaseDamage: 10                # 基础伤害
PostureDamage: 5              # 基础架势伤害
HitStartTime: 0.23            # 前摇结束，进入命中段
RecoveryWindowStart: 0.5      # 后摇开始，重新开放取消/移动/连招
ComboWindowEnd: 0.66          # 连招输入截止
StateDuration: 1.467          # 状态总时长
AllowRotation: 1              # 允许起手转向目标
RotationWindowEnd: 0.3        # 转向窗口结束
NextCombo: atk2               # 下一段连招
hitPulses:
  - start: 0.23               # 判定开启
    end: 0.5                  # 判定关闭
    overrideCombat: 0         # 0 = 沿用 BaseDamage / PostureDamage
```

这份配置里有两组含义不同的时间：

- **节奏窗口**（`HitStartTime / RecoveryWindowStart / ComboWindowEnd`）：决定动作在什么时间能被取消、能接移动、能接连招；
- **判定脉冲**（`hitPulses`）：决定 Hitbox 什么时候开、什么时候关。`HitStartTime` 本身不开启 Hitbox。

两组数值可以对齐（`atk1` 就是对齐的），但逻辑上相互独立，所以一招可以配置多段判定。

```text
0.00s            0.23s              0.50s         0.66s              1.467s
  │                │                  │             │                  │
  ├─── 前摇 ───────┼─── 命中段 ───────┼── 后摇 ─────┼─── 后摇尾段 ─────┤
  │  可取消        │ 不可取消         │ 可取消/移动 │ 连招窗口已截止   │
  │                │ Hitbox [0.23, 0.50) 开启       │                  │
                                      └─ 连招窗口 [0.50, 0.66] ─┘
```

取消规则写在 `AttackStateBase.HandleCommand` 里：前摇和后摇可以取消，命中段锁定。

```csharp
// AttackStateBase.cs
bool canCancel = animTime < config.HitStartTime ||
                 animTime >= config.RecoveryWindowStart;
```

### 4. 一次攻击的四个阶段
`AttackStateBase` 的三个生命周期方法加上状态切换，把一次攻击分成四个阶段：

```text
阶段一  OnEnter            进入状态：重置运行时数据，起手对准目标，同步判定记账
阶段二  OnUpdate（每帧）   读动画时钟 animTime，驱动后面所有按时间触发的逻辑
阶段三  ApplyHitbox（每帧）按 animTime 开关 Hitbox，维护命中去重
阶段四  ExitToIdle / OnExit 正常结束或被打断后收尾，关闭判定、归还控制权
```

`OnUpdate` 是中间两个阶段的入口，每帧按固定顺序做下面这些事：

```csharp
// AttackStateBase.cs
public override void OnUpdate()
{
    // 空中刀落地由 AirState.LeaveAir 切回地面；落地帧不再推进本刀（地面恒 false）
    if (WantsImmediateLand) return;

    // ① 读动画时钟，得到本招已经播放的秒数
    animTime = AttackAnimClock.ReadSeconds(body.Animator, config.AnimName);

    // ② 到达后摇起点，开放取消标记
    body.IsAttackRecoveryOpen = animTime >= config.RecoveryWindowStart;

    // ③④ 同步命中、音效、出箭：都以 animTime 为准，动画变速时一起跟随
    ApplyHitbox();
    ApplySfx();
    ApplyArrows();

    // ⑤ 允许转向的招式：持续对准目标
    if (config.AllowRotation)
    {
        UpdateAttackSteer();
    }

    // 位移不在此处理：突进/前移完全由攻击动画的 Root 曲线驱动（全权根运动），
    // 代码只负责状态时长与连招窗口判定

    // ⑥ 判断是否结束
    bool noMelee = !AttackWindowSync.CanMeleeHit(config.hitPulses);
    bool animFinished = IsAnimFinished(config.AnimName);
    bool animPlayedOut = config.NextCombo == null
        && animTime >= LastHitWindowEnd()
        && animFinished;
    if (config.WaitAnimEnd)
    {
        if (animFinished)
            ExitToIdle();
    }
    else if (animTime >= config.StateDuration || animPlayedOut || (noMelee && animFinished))
    {
        ExitToIdle();
    }
}
```

## 2. 阶段一：进入状态（AttackStateBase.OnEnter）

### 1. 谁调用、执行哪一份实现
`SubStateMachine.ChangeState(new AttackState(...))` 把新状态设为 `CurrentState` 后调用 `OnEnter()`。`AttackState` 没有重写 `OnEnter()`，所以执行的是 `AttackStateBase.OnEnter()`。它开头先调用虚方法 `OnAttackEnter()`：空中攻击子类用它记录进入时刻，地面子类不实现。

`OnEnter` 要做的事可以概括成三件：

1. 把运行时数据清到初始状态，并把本招的伤害数值存下来，避免带着上一招的时钟、脉冲记账；
2. 请求播放攻击动画，起手先对准目标，同时屏蔽动画自带的根旋转；
3. 把判定记账同步到“Hitbox 关闭”的初始状态。

### 2. 源码
```csharp
// AttackStateBase.cs
public override void OnEnter()
{
    OnAttackEnter();   // 子类钩子

    // 重置时钟和各类记账；伤害、架势、击退、命中等级先存一份作为默认值。
    animTime = 0f;
    sfxFired = null;
    arrowFired = null;
    body.IsAttackRecoveryOpen = false;
    fallbackDamage = config.BaseDamage;
    fallbackPosture = config.PostureDamage;
    fallbackKnockback = config.Knockback;
    fallbackGrade = config.HitGrade;
    moveEntry = body.CurrentMoveEntry;
    moveWindow = body.CurrentMoveWindow;
    activePulseIndex = -1;

    // ActiveAttack 是 Brain 对“下一次攻击”的一次性选择，状态取得后立即清空。
    if (body.ActiveAttack == config)
    {
        body.ActiveAttack = null;
    }

    // 校验窗口顺序：HitStartTime <= RecoveryWindowStart <= ComboWindowEnd <= StateDuration。
    // 配置不合法就直接退回待机，不进入这一招。
    if (!ValidateWindows())
    {
        ExitToIdle();
        return;
    }

    // 请求攻击动画；JumpThrust 直接播放，其余招式淡入。
    bool attackAnimStarted = AnimUtil.TryBeginAttackAnim(body.Animator, config, body.CurrentMoveEntry);
    if (!attackAnimStarted)
    {
        Debug.LogError($"{body.name} 的 Animator 缺少攻击状态：{config.AnimName}");
    }

    // 允许转向的招：起手先对准目标，整招丢掉 Clip 根旋转。
    // 否则挥砍动画自带的 Root yaw 会盖掉代码算出的朝向。
    body.ClearCombatYawFrozen();
    body.SetSuppressRootYaw(config.AllowRotation);
    if (config.AllowRotation)
    {
        SnapTowardCombatTarget();
        UpdateAttackSteer();
    }

    // 判定只跟随 hitPulses；先把“Hitbox 是否开启”的记账置为 false，再同步一次。
    weaponHitEnabled = false;
    ApplyHitbox();

    // 霸体标记；危字攻击还要广播事件，UI 弹出“危”字提示。
    body.AttackUninterruptible = IsUninterruptibleAttack(config, body.CurrentMoveEntry);
    if (config.Perilous != PerilousType.None)
    {
        CombatEventBus.TriggerPerilousAttack(config.Perilous);
    }
}
```

### 3. 末尾这次 ApplyHitbox 做了什么
进入状态时 `animTime = 0`，而 `atk1` 的第一个脉冲从 `0.23s` 开始，所以：

- `CurrentPulseIndex()` 返回 `-1`，`wantOn = false`；
- `weaponHitEnabled` 刚被置为 `false`，两个分支条件都不成立，不会调用 `EnableWeaponHit`；
- 方法末尾把 `body.ActiveHitPulseIndex` 写成 `-1`。

也就是说，这一步让本次攻击以“判定未开启”的记账状态起步，没有开启 Hitbox。需要注意它不会主动调用 `DisableWeaponHit()`：上一个状态遗留的 Hitbox 是否已关闭，由上一个状态自己的 `OnExit` 保证（见第 5 节）。如果某个脉冲配置成 `start = 0`，则这次调用会在进入状态的当帧直接开启判定。

## 3. 阶段二：动画时钟（AttackAnimClock）

### 1. 为什么不用 Animation Event
开关判定的常见做法是在动画 Clip 上放 Animation Event。本项目不用，改为每帧读动画进度、用配置里的秒数比较：

| | Animation Event | 代码时钟（`AttackAnimClock`） |
| :--- | :--- | :--- |
| 帧率波动 | 事件挂在 Clip 的某个时间点上，是否触发取决于动画更新；依赖事件开关 Hitbox 时，一旦漏触发，判定就开不出来或关不掉 | 每帧算出 `animTime`，用区间 `[start, end)` 比较，不依赖某个时间点是否被“踩到” |
| 中途被打断 | 状态被切走，后面的“关闭事件”不会再触发，需要另外兜底 | 开关逻辑在状态里，状态退出时 `OnExit` 统一关闭 |
| 资产维护 | 事件绑在 Clip 上，重导模型或替换动画需要重新检查事件 | 时间点存在 `AttackConfig` 里，与 Clip 分开维护 |

### 2. 谁在每帧调用 OnUpdate
Unity 只会调用 `MonoBehaviour` 的 `Update`，状态机由 `CharacterBody` 逐层驱动：

```text
CharacterBody.Update()
  └─ MainStateMachine.Update()
      └─ StateMachine.Update()  →  CurrentState.OnUpdate()
          └─ GroundedState.OnUpdate()
              ├─ 先检查是否离地（离地则 EnterAirborne 并 return）
              └─ base.OnUpdate()  →  HierarchicalState.OnUpdate()
                  └─ SubStateMachine.Update()  →  CurrentState.OnUpdate()
                      └─ AttackStateBase.OnUpdate()   （AttackState 未重写）
```

```csharp
// CharacterBody.cs
private void Update()
{
    UpdateEnvironmentalChecks();
    UpdateFallSafety();
    UpdatePostureDecay();
    MainStateMachine.Update();   // 主状态机会一层层往下驱动子状态机
}

// StateMachine.cs
public void Update()
{
    CurrentState?.OnUpdate();
}

// GroundedState.cs
public override void OnUpdate()
{
    if (!body.IsGrounded && !body.IsPostureBroken && !body.IsParried && !body.IsFinisherLocked && body.UsesAirState)
    {
        body.EnterAirborne("grounded: left ground");
        return;
    }

    base.OnUpdate(); // 更新当前子状态，包含待机、移动、攻击等。
}

// HierarchicalState.cs
public override void OnUpdate()
{
    SubStateMachine.Update();
}
```

### 3. ReadSeconds：把动画进度换成秒
`OnUpdate` 第一步调用 `AttackAnimClock.ReadSeconds`，把 Animator 里当前攻击动画的进度换算成秒，结果存在 `animTime`：

```csharp
// AttackAnimClock.cs
public static class AttackAnimClock
{
    public const int Layer = 0;

    public static float ReadSeconds(Animator animator, string animName)
    {
        int hash = Animator.StringToHash(animName);

        // 混合期间优先读目标状态，让新攻击从自己的动画时间开始推进。
        if (animator.IsInTransition(Layer))
        {
            AnimatorStateInfo next = animator.GetNextAnimatorStateInfo(Layer);
            if (next.shortNameHash == hash)
                return SecondsFrom(next);
        }

        AnimatorStateInfo current = animator.GetCurrentAnimatorStateInfo(Layer);
        if (current.shortNameHash == hash)
            return SecondsFrom(current);

        // 目标攻击尚未成为当前/下一动画时，从 0 等待；不借用上一动作的时间推进新招判定。
        return 0f;
    }

    static float SecondsFrom(AnimatorStateInfo info)
    {
        if (info.length <= 0.0001f)
            return 0f;
        // 归一化进度 × 状态长度，换算成攻击配置使用的动画内秒数；不是全局 Time.time。
        return info.normalizedTime * info.length;
    }
}
```

关键在淡入期间的处理。攻击动画是淡入进来的（`TransitionDuration: 0.1`），这段时间里 Animator 的“当前状态”还是上一个动作（待机或上一刀）。如果这时读当前状态，`animTime` 会是上一个动作的进度，新招可能一开始就被判断成已经过了前摇。所以代码先看过渡的目标状态：如果目标就是本招，就读目标状态的进度；两边都不是本招时返回 `0`，等动画真正切过来。

## 4. 阶段三：开关 Hitbox（ApplyHitbox）

### 1. 为什么不能每帧重复开启
`WeaponController.EnableWeaponHit` 最终调用 `Hitbox.SetConfig` 和 `Hitbox.Enable`，这两个方法都会清空 `Hitbox` 里的已命中集合 `hitTargets`：

```csharp
// Hitbox.cs
// 已命中记录：防止一次挥砍对同一目标多次结算
private readonly HashSet<CharacterBody> hitTargets = new HashSet<CharacterBody>();

public void SetConfig(AttackConfig config)
{
    this.config = config;
    hitTargets.Clear();
}

public void Enable()
{
    ...
    isActive = true;
    lastCastPos = transform.position;
    hitTargets.Clear();
    ...
}
```

`hitTargets` 保证一次挥刀对同一个敌人只结算一次。命中判定持续 `0.23s ~ 0.50s`（约 16 帧）。如果每帧在窗口内都调用一次 `EnableWeaponHit`，集合每帧被清空，贴身的敌人每帧都会被重新结算，一刀就可能被打 16 次。

所以 `ApplyHitbox` 只在状态变化的那一帧开或关：进入脉冲时开一次、离开脉冲时关一次，脉冲中间不动。

### 2. 四个变量
| 变量 | 生命周期 | 含义 |
| :--- | :--- | :--- |
| `pulseIndex` | 方法内局部 | 当前 `animTime` 落在第几个脉冲里，没有则为 `-1` |
| `wantOn` | 方法内局部 | 按配置，这一帧 Hitbox 应不应该开（`pulseIndex >= 0`） |
| `weaponHitEnabled` | 状态内成员 | 记账：Hitbox 当前是不是已经被本状态开启 |
| `activePulseIndex` | 状态内成员 | 记账：当前开启的是哪一个脉冲 |

`pulseIndex / wantOn` 表示“这一帧应该是什么样”，两个成员表示“上一帧已经是什么样”，比较这两组值就知道要不要操作 Hitbox。

### 3. 源码
```csharp
// AttackStateBase.cs
// 只按有效 hitPulses 开关判定；脉冲变化也重开，以更新伤害并清除上一刀的命中记录。
// HitStartTime 和 RecoveryWindowStart 用于取消与连招窗口，不直接开关 Hitbox。
private void ApplyHitbox()
{
    int pulseIndex = -1;
    bool wantOn = false;
    if (AttackWindowSync.CanMeleeHit(config.hitPulses))
    {
        pulseIndex = CurrentPulseIndex();   // 遍历脉冲，找出 animTime 落在 [start, end) 的那一个
        wantOn = pulseIndex >= 0;
    }

    bool pulseChanged = wantOn && pulseIndex != activePulseIndex;

    if (wantOn && (!weaponHitEnabled || pulseChanged))
    {
        // 分支 1：进入脉冲，或从一个脉冲换到下一个脉冲
        if (weaponHitEnabled)
            body.DisableWeaponHit();        // 换段时先关再开
        ApplyPulseCombat(pulseIndex);       // 装载这一段的伤害数值
        body.EnableWeaponHit(config);       // 开 Hitbox，同时清空 hitTargets
        weaponHitEnabled = true;
        activePulseIndex = pulseIndex;
    }
    else if (!wantOn && weaponHitEnabled)
    {
        // 分支 2：离开脉冲
        body.DisableWeaponHit();
        weaponHitEnabled = false;
        activePulseIndex = -1;
    }
    // 分支 3：其余情况什么都不做。
    // 例如已在脉冲内（wantOn && !pulseChanged）：保持开启，不清空 hitTargets。

    body.ActiveHitPulseIndex = wantOn ? pulseIndex : -1;
}
```

```text
每帧：pulseIndex = CurrentPulseIndex()，wantOn = (pulseIndex >= 0)
  │
  ├─ wantOn 且（Hitbox 未开 或 换了脉冲）
  │    关旧（如有）→ 装载伤害 → EnableWeaponHit（清空 hitTargets）→ 记账为开启
  ├─ 不 wantOn 且 Hitbox 已开
  │    DisableWeaponHit → 记账为关闭
  └─ 其他：不操作
```

### 4. 以 atk1 逐段推演
| animTime | pulseIndex | wantOn | weaponHitEnabled（进入前） | 走哪个分支 | 结果 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 0.00 ~ 0.22 | -1 | false | false | 无 | 保持关闭 |
| 0.23（首帧） | 0 | true | false | 分支 1 | 开启 Hitbox，清空 `hitTargets`，记账为开启 |
| 0.24 ~ 0.49 | 0 | true | true | 无 | 保持开启，`hitTargets` 保留，已命中的人不再重复结算 |
| 0.50（首帧） | -1 | false | true | 分支 2 | 关闭 Hitbox，记账为关闭 |

## 5. 阶段四：结束与收尾

### 1. 正常结束：什么时候调用 ExitToIdle
第 1 节里 `OnUpdate` 末尾的判断有三种满足方式（`WaitAnimEnd = false` 时）：

- `animTime >= StateDuration`：到达配置时长；
- `animPlayedOut`：没有下一段连招，判定窗口已经过完，且动画真正播完；
- `noMelee && animFinished`：这一招没有近战脉冲（如纯远程招式），动画播完即结束。

`WaitAnimEnd = true` 时只看动画是否播完。后两条用来避免没有后续的动作停在动画最后一帧。

`atk1` 有近战脉冲（`noMelee = false`），配置了 `NextCombo`（`animPlayedOut = false`），所以由 `animTime >= 1.467s` 触发。满足后调用子类的 `ExitToIdle()`：

```csharp
// AttackState.cs
protected override void ExitToIdle()
{
    parent.SubStateMachine.ChangeState(new IdleState(body, parent), "attack: finished");
}
```

### 2. 被打断：状态在中途被切走
正常流程里，`0.50s` 时 `ApplyHitbox` 的分支 2 会关闭 Hitbox。但攻击过程中角色可能被打断：

- 被对方完美弹反，进入弹刀硬直；
- 被敌人击中，进入受击硬直（`StunnedState`）；
- 后摇里主动取消成闪避或弹反。

这些情况下，状态在 `0.30s` 之类的时刻就被换走，`animTime` 不会再走到 `0.50s`，`ApplyHitbox` 也没有机会再执行。如果 Hitbox 靠“时钟走到窗口末尾”才关，它就会一直开着。

这个问题由状态机的退出规则解决：不管因为什么原因离开某个状态，`ChangeState` 都会先调用旧状态的 `OnExit()`。如果切换发生在父层（例如主状态机从 `GroundedState` 切到受击状态），`HierarchicalState.OnExit` 会先让子状态机退出当前子状态（`SubStateMachine.ChangeState(null, ...)`），攻击状态的 `OnExit` 同样会被调用。

```csharp
// HierarchicalState.cs
public override void OnExit()
{
    // 离开父状态也要退出子状态，...
    SubStateMachine.ChangeState(null, "parent: exit child");
}
```

### 3. OnExit：统一收尾
```csharp
// AttackStateBase.cs
public override void OnExit()
{
    // 正常结束和被打断都会经过这里，必须关掉判定，避免离开攻击后仍能打中别人。
    body.DisableWeaponHit();             // 关闭 Hitbox（同时清空命中记录）
    body.ActiveHitPulseIndex = -1;       // 清脉冲索引
    body.IsAttackRecoveryOpen = false;   // 后摇标记复位
    body.AttackUninterruptible = false;  // 清除霸体标记
    body.SetSuppressRootYaw(false);      // 把根旋转还给动画
}
```

因此关闭 Hitbox 有两个入口：正常时间到期时由 `ApplyHitbox` 关，任何方式离开状态时由 `OnExit` 关。`OnEnter` 对应地把 `OnExit` 清掉的那几项在新状态里重新建立。

## 6. 以 atk1 串起整个生命周期

```text
0.00s   IdleState 收到 AttackCommand，ChangeState(new AttackState)
        OnEnter：重置时钟与记账，起手对准目标，ApplyHitbox 同步为“未开启”
0.23s   animTime 进入脉冲 0
        ApplyHitbox 分支 1：EnableWeaponHit，Hitbox 开启，hitTargets 清空
0.30s   仍在脉冲 0 内
        不操作 Hitbox，已命中目标不重复结算
0.50s   animTime 离开脉冲 0
        ApplyHitbox 分支 2：DisableWeaponHit；
        同时 IsAttackRecoveryOpen = true，开放取消、移动与连招
0.66s   ComboWindowEnd 到期
        此后收到攻击指令不再派生二段
1.467s  animTime >= StateDuration
        ExitToIdle → ChangeState → 旧状态 OnExit 收尾，回到待机

被打断（任意时刻）：
        状态被切走 → OnExit 关闭 Hitbox 并复位标记
```
