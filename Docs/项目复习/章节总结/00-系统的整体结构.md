## 1. 战斗全流程：六大子系统的分工与数据流

整场 Boss 战由六个子系统协作完成，一条动作从产生意图到结算表现按以下顺序流转：

```text
【战斗六大子系统与数据流闭环】
1. 意图驱动层 (Brain)
   ├─ 玩家端: PlayerBrain (摇杆移动采集 + 0.2s 单槽离散动作缓冲池)
   └─ Boss端: BTBrain (行为树评估距离/冷却/权重生成动作请求)
       │ (提交 Command / 意图)
       ▼
2. 角色与动作控制 (Body & HFSM)
   ├─ 角色门面: CharacterBody (聚合状态机、动画、刚体、运动、朝向、武器与数值控制器)
   └─ 分层状态机: HFSM (顶层 Grounded / Air / Stunned / Dead 环境与子状态机动作切换)
       │ (播放动作与推进时钟)
       ▼
3. 动作推进与表现层 (Anim & Clock)
   ├─ 动画推进: Animator (骨骼动作融合 CrossFade 与根运动 Root Motion)
   └─ 代码时钟: AttackAnimClock (按绝对秒数计算动画进度，驱动判定窗口与取消窗口)
       │ (按脉冲窗口启停判定槽位)
       ▼
4. 物理检测与去重 (Hitbox & Query)
   ├─ 部件管理: WeaponController (负责刀刃、肘击、踢腿等 Hitbox 槽位启停与配置注入)
   └─ 几何查询: Hitbox (LateUpdate 执行 SphereCastAll 位移扫掠 + OverlapSphereNonAlloc 刀尖重叠
                       + OverlapCapsuleNonAlloc 刀柄至刀尖胶囊检测 + hitTargets 集合去重)
       │ (经 CombatManager.ReportHit 上报命中参数)
       ▼
5. 攻防裁决与数值 (Resolver & Stats)
   ├─ 中枢转发: CombatResolver (将命中参数转发至防守方 CharacterBody.ReceiveHit 组装 HitData)
   ├─ 防御裁决: 防守方按当前状态裁决 (DodgeState 无敌或看破 / DeflectState 完美弹反或普通格挡 / 肉身受击)
   └─ 数值维护: CombatStats (维护运行时 HP 与架势值，架势打满触发 OnPostureBroken 回调)
       │ (发布事件与触发顿帧)
       ▼
6. 表现广播与生命周期 (Bus & Director)
   ├─ 事件总线: CombatEventBus (广播血量/架势变化、格挡火花音效、相机震动与刀光起止 TriggerAttackSwingStart/End)
   ├─ 顿帧控制: TimeScaleController (由 CombatManager 与 DeflectState 直接调用 HitStop 修改时间尺度)
   └─ 决胜闭环: DuelDirector (管理双人同步忍杀演出、胜负判定与场内复位)
       └─ [闭环反馈] 处决演出锁 (IsFinisherLocked) 吞噬外界输入并切入地面处决子状态 (FinisherState)
```

### 六个子系统的职责边界

1. **意图驱动层（`Brain`）**：
   - 只决定“想做什么”，不直接操作动画或物理组件；
   - 玩家端（`PlayerBrain`）读取输入并维护 0.2s 单槽缓冲池；Boss 端（`BTBrain`）由行为树结合黑板条件（距离、冷却、权重）选出动作；
   - 双方最终都通过 `CharacterBody` 提交 `ICommand` 指令或动作请求。
2. **角色与动作控制（`Body & HFSM`）**：
   - 决定当前“能不能做、切到哪个状态”；
   - `CharacterBody` 持有顶层 `MainStateMachine`（管理 `GroundedState`、`AirState`、`StunnedState`、`DeadState` 四大顶层环境），地面和空中父状态各自持有 `SubStateMachine` 管理具体动作子状态（如 `IdleState`、`MoveState`、`AttackState`、`DeflectState`、`DodgeState`、`HealState`、`MidToGuardState`、`StandingState`、`ParriedState`、`StaggerBrokenState`、`FinisherReadyState`、`FinisherState` 等）。
3. **动作推进与表现层（`Animator & Clock`）**：
   - C# 状态类负责逻辑判断，Unity `Animator` 负责播放骨骼动画与提供 Root Motion；
   - 不用 Unity Animation Event，`AttackAnimClock` 在 `OnUpdate` 中按 `normalizedTime * length` 算出当前绝对秒数，驱动判定与取消窗口。
4. **物理检测与去重（`Combat`）**：
   - `WeaponController` 管理武器、拳脚等部位的 `Hitbox` 槽位；
   - `Hitbox` 在 `LateUpdate` 中先对帧间位移做 `SphereCastAll` 扫掠（防高速挥刀穿模），再通过 `FillOverlapping` 做刀尖 `OverlapSphereNonAlloc` 与刀柄至刀尖 `OverlapCapsuleNonAlloc`（`shaftRadius`，防连招起点已重叠及贴身站在挥砍内侧时刀尖从身侧刮过漏判），并用 `hitTargets` 集合保证单段挥刀对同一目标只结算一次。
5. **攻防裁决与数值（`Resolver & Stats`）**：
   - 扫到碰撞体不直接扣血：`Hitbox` 经 `CombatManager.ReportHit` $\rightarrow$ `CombatResolver.ReportHit` 转发给防守方 `CharacterBody.ReceiveHit`（封装为 `HitData`），由防守方当前状态的 `OnHitReceived` 先行拦截裁决；
   - `CombatStats` 维护角色运行时的血量与架势值，架势打满时触发 `OnPostureBroken` 回调。
6. **表现广播与生命周期（`Bus & Director`）**：
   - `CombatEventBus` 用静态 C# `event` 向 UI、音效、相机和刀光组件广播状态变化（其中刀光起止由 `TriggerAttackSwingStart/End` 广播，而命中/弹反顿帧由 `CombatManager` 和 `DeflectState` 直接调用 `TimeScaleController.HitStop()`）；
   - `DuelDirector` 负责忍杀处决时的双人位置朝向对齐、演出锁（`IsFinisherLocked`）以及战败回生或场内重置。

## 2. `CharacterBody`：角色门面与组件聚合

`CharacterBody` 挂在角色根节点上，对外提供统一的调用入口，内部持有状态机、Unity 组件和各专职子控制器：

```text
CharacterBody (角色门面)
  │
  ├─ [状态机与引擎组件]
  │    ├─ MainStateMachine             ─── 顶层状态机 (驱动 Grounded / Air / Stunned / Dead)
  │    ├─ Animator                     ─── 骨骼动画组件 (CrossFade 融合、OnAnimatorMove 根位移)
  │    └─ Rigidbody                    ─── 物理刚体 (移动速度写入与碰撞约束)
  │
  ├─ [内部子控制器]
  │    ├─ CharacterLocomotion (Loco)   ─── 运动控制器 (地面检测、斜坡投影、重力与水平速度写入)
  │    ├─ CharacterFacing (Facing)     ─── 朝向控制器 (RotateYaw 平滑转向、SnapYaw 瞬时对齐、SetSteerYaw 挥刀追踪)
  │    ├─ WeaponController (Weapons)   ─── 武器控制器 (按槽位开启/关闭 Hitbox、注入当前段 AttackConfig)
  │    ├─ CombatStats (Stats)          ─── 战斗数值实例 (当前 HP、当前架势、架势自然恢复、崩解与死亡回调)
  │    └─ DeflectAttemptTracker        ─── 弹反追踪器 (生成按键 PressId、计算弹反窗口与连续空按缩窗惩罚)
  │
  └─ [只读配置资产]
       └─ CharacterConfig              ─── ScriptableObject 资产 (基础血量、架势上限與恢复速率、移动与弹反参数)
```

### 两条结构约束

- **静态配置与运行时数据分离**：`CharacterConfig` 和 `AttackConfig` 是只读的 `ScriptableObject` 资产；运行时会变化的血量、架势、弹反空按计数、当前激活脉冲索引分别存在角色自己的 `CombatStats`、`DeflectAttemptTracker` 和 `CharacterBody` 字段里。
- **状态通过 `body` 调子控制器**：各个状态类（如 `AttackState`、`DeflectState`）只持有 `CharacterBody body` 引用。开关判定调 `body.EnableWeaponHit` / `body.DisableWeaponHit`，转向调 `body.RotateYaw` / `body.SnapYaw` / `body.SetSteerYaw`，扣血涨架势调 `body.TakeDamage` / `body.AccumulatePosture`，不在状态类里直接持有底层子控制器引用。

## 3. 一次攻防交互的跨模块调用全景

把“攻击方出刀”和“防守方响应”放在同一条时间线上，跨模块的完整调用顺序如下：

```text
【阶段 A：意图与出招】
1. 攻击方提交意图：PlayerBrain 收集按键 (或 Boss BTBrain 行为树选招) 调用 body.TryExecuteCommand；
2. 状态切换：攻击方 HFSM 校验通过，切入 AttackState；
3. 时钟驱动：AttackAnimClock 在 OnUpdate 中算出当前动画秒数 animTime，进入脉冲区间时调 WeaponController 开启对应槽位 Hitbox；
4. 几何查询：Hitbox 在 LateUpdate 中执行 SphereCastAll 位移扫掠 + OverlapSphereNonAlloc 刀尖重叠 + OverlapCapsuleNonAlloc 刀身胶囊检测，扫到防守方的 Hurtbox。

【阶段 B：命中转发与防御裁决】
5. 上报命中：Hitbox.TryHit 将目标记入 hitTargets 去重集合，调用 CombatManager.ReportHit（转交 CombatResolver.ReportHit，并调用 TimeScaleController.HitStop 触发顿帧）；
6. 目标入口：CombatResolver 调用防守方 CharacterBody.ReceiveHit(...)，内部将攻击者、伤害、危字类型、受击等级打包为 HitData；
7. 状态拦截裁决：防守方先检查 Boss 被动防御 TryPassiveDeflect，再调用 MainStateMachine.CurrentState.OnHitReceived(hit) 逐层裁决：
   ├─ 处于 DodgeState (无敌帧内或成功看破危字突刺) ─── 返回 true 拦截命中，不扣血（看破则调攻方 ForceMikiriStun）；
   ├─ 处于 DeflectState (完美弹反窗内)           ─── 返回 true：攻击方 AccumulatePosture 涨架势（末刀调 ForceParryStun 切入 ParriedState），防守方不涨架势（仅调 MarkCombatTime），触发 HitStop 与打铁事件；
   ├─ 处于 DeflectState (普通格挡期)             ─── 返回 true：免除 HP 伤害，防守方按 GuardPostureFactor 比例涨架势并播格挡受击动画；
   └─ 处于 Idle / Attack 等无防御状态            ─── OnHitReceived 返回 false，继续向下执行 ReceiveHit 的肉身受击结算。

【阶段 C：数值结算与表现反馈】
8. 扣血与硬直：ReceiveHit 调用 TakeDamage 结算 HP 与架势（若未致死则调 NotifyDeflectHitFailed 结束未成功的弹反尝试），再按受击等级切入 StunnedState（若架势打满则由回调切入 StaggerBrokenState）；
9. 事件广播：CombatStats 与各状态通过 CombatEventBus 触发事件，UI 更新血条和架势条，音效与相机震动同步响应；
10. 忍杀收尾：当一方架势崩解且触发 FinisherCommand 时，DuelDirector 锁死双方输入 (IsFinisherLocked = true)，双方分别切入 FinisherState 与 FinisherVictimState 完成同步处决。
```
