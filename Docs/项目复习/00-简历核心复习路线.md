# 《只狼》Boss 战：简历核心复习路线（高效实战版）

更新日期：2026-10-21。
**核心原则**：在 3～4 天的时间约束下，坚决不搞无意义的全项目文件通读；坚持**“代码是切片探针，机制才是复习主干”**。以最小的代码阅读量，吃透最核心的系统架构与设计取舍，在面试中能够自如应对深度追问。

## 学习阶段与掌握标准

后续统一使用“阶段二 · 章节 2：Command 与 HFSM 动作切换”此类格式定位。

### 阶段一：建立架构全貌与交接网络
- **目标**：建立整场战斗的全局网络。明确各子系统的职责边界、谁调用谁、数据如何流转。
- **掌握标准**：能画出或讲清从“意图（玩家/Boss）$\rightarrow$ 动作（HFSM）$\rightarrow$ 检测（Hitbox）$\rightarrow$ 裁决（ReceiveHit）$\rightarrow$ 数值（CombatStats）$\rightarrow$ 表现（EventBus）”的闭环网络；知道 `CharacterBody` 门面如何聚合底层专职控制器。
- **边界**：不在此阶段抠具体算法分支或具体方法的行级代码。

### 阶段二：吃透核心系统机制（精读关键切片）
- **目标**：推进核心功能章节。AI 提供关键真实源码和顺序，学习者顺着代码跟通一个具体场景的执行过程，并横向对比关键分支。
- **掌握标准**：
  1. **数据来源**：知道关键输入、配置（SO）来自何处，运行时数据（HP/架势/时钟）由谁维护；
  2. **路由与条件**：理解正常分支为何成立，关键判断判定什么，随后调用谁；
  3. **状态变化**：理解执行后哪些状态/标志位改变，如何影响下一次轮询；
  4. **边界与打断**：理解动作结束收尾，以及一个关键打断（如处决锁吞噬、后摇打断、弹反打断）的清理与安全保障。
- **边界**：不要求脱离源码手写整个系统，不穷尽所有边缘招式与特例；重点在通用控制逻辑与架构设计。

### 阶段三：提炼设计取舍与面试表达
- **目标**：在功能理解后，提炼“为什么这样设计”、“解决了什么痛点”、“付出什么代价”、“有哪些边界局限”。
- **掌握标准**：能够结合简历要点，用准确的技术语言阐述 Command 模式、HFSM 分层、SphereCast 扫掠去重、防御裁决与行为树分工。

## 固定讲解与总结规范

1. **机制为主，案例为引**：
   具体游戏场景（如轻攻击 `atk1`）**仅作为验证代码的执行探针**。讲解与章节总结必须以**通用机制**（如多指令路由、跨层拦截、取消窗口、完整攻防裁决）为主干，案例仅作佐证，**严禁将章节总结写成单一招式的单线流水账**。
2. **以点带面，对比分支**：
   讲解主线时，必须横向对比一个关键分支（如：讲待机切攻击时，必须对比父层截胡跳跃与动作后摇打断闪避），展现系统的立体裁决能力。
3. **顺着时序给代码**：
   AI 按真实执行时序贴出核心代码切片，讲清谁调用、参数来源、变量语义与状态变化，简单转发合并，关键判断展开。
4. **总结即武器库**：
   章节总结必须保持独立性与纯粹性，直接从 `## 1.` 起始，无死链，垂直排版适配，专注文档架构与数据流，作为可直接导入外部笔记软件的终极面试复习文档。

## 简历核心要点对照（求职弹药库）

1. **角色控制架构**：Command + HFSM。将玩家输入与 Boss 常规动作请求统一抽象为指令，通过网关、父状态优先拦截、子状态自治与取消窗口实现严密的动作切换与打断。
2. **物理检测与去重**：配置化时间窗口启停 Hitbox，采用 `SphereCastAll` 扫掠与 `OverlapSphere` 贴身重叠检测，结合攻击段内受击去重列表，解决高速挥刀穿模与近身重复结算。
3. **战斗裁决与防御机制**：接触不等于扣血，通过 `CombatResolver` 转发至受击方 `ReceiveHit`，依自身状态即时裁决无敌帧、完美弹反、普通格挡与肉身受击，解耦攻击与受击逻辑。
4. **Boss 行为决策**：轻量行为树与黑板，结合距离、冷却、权重筛选招式，分离“AI 决策”与“角色动作执行”。
5. **数据与表现解耦**：ScriptableObject 静态配置与运行时动态数据严格分离；通过静态事件总线 `CombatEventBus` 广播驱动 UI 与音效。

## 核心复习章节规划（3～4 天高密度路线）

### 章节 1：项目全貌与角色内部结构（全局协同网络）
- **定位**：建立全局认知，不做局部发散。
- **核心内容**：
  - 战斗六大子系统协同网络闭环（意图 $\rightarrow$ HFSM $\rightarrow$ 表现/时钟 $\rightarrow$ 物理判定 $\rightarrow$ 裁决数值 $\rightarrow$ 事件表现）；
  - `CharacterBody` 门面模式：统一聚合状态机、动画、刚体、运动、朝向、武器与战斗数值控制器，对外暴露简洁接口；
  - 静态配置（ScriptableObject）与角色运行时实例（`CombatStats`）的数据隔离设计；
  - 攻防对抗的系统级跨模块交互全景（攻守双方在同一时空下的协同流转）。
- **停止边界**：掌握模块职责与交接网络，不展开任何具体招式或具体几何算法。

### 章节 2：一次输入怎样切换角色动作（Command + HFSM 动作中枢）
- **定位**：掌握动作切换的核心调度机制。
- **入口与范围**：
  - 驱动源头：`PlayerBrain.Update()` 采集摇杆与长按突刺，显式调用 `base.Update()` 轮询单槽缓冲池 `ProcessCommandBuffer`；
  - 连续移动（逐帧直通无缓冲）与离散动作指令（0.2s TTL 单槽缓冲池）的双轨设计；
  - **HFSM 四级分流裁决模型（核心）**：
    1. 统一网关：`TryExecuteCommand` 中的处决演出锁主动吞噬（返回 true 防穿透）；
    2. 父层截胡：地面父状态 `GroundedState.OnParentHandleCommand` 捕获跳跃 `JumpCommand`，直接切换至 `AirState`，**指令不传子状态**；
    3. 子层自治：待机 `IdleState` 响应 `AttackCommand` / `DodgeCommand` / `DeflectCommand`，执行同层原子切态；
    4. 动作打断：挥刀 `AttackState` 接收闪避，前摇拒收（缓冲池等待），后摇取消窗口（Recovery Window）开放时立即打断切态；
  - 状态切换的原子性流转（`ChangeState` 4 步）与级联退出（Cascade Exit）的安全底线。
- **重点追问**：Command 模式为什么能同时驱动玩家与 Boss？父层返回 false 为什么代表放行而非拒绝？演出锁为什么必须返回 true？
- **停止边界**：以待机切攻击、跳跃截胡、后摇打断为对比切片，不展开所有特殊技能与摄像机。

### 章节 3：一次动作的具体生命周期（时钟、判定算法与收尾）
- **定位**：微观动作执行专精（以普通攻击为例）。
- **入口与范围**：
  - `AttackConfig`：招式动画、时长、取消窗口与近战脉冲（`hitPulses`）；
  - 进入与初始化：`AttackStateBase.OnEnter` 重置时钟、锁存伤害、首帧关闭判定；
  - 时钟驱动：为什么弃用 Animation Event？`AttackAnimClock` 纯代码提取绝对秒数的计算逻辑；
  - **近战判定核心控制（重点）**：`ApplyHitbox` 状态机决策算法，`pulseIndex / wantOn / weaponHitEnabled / activePulseIndex` 四个控制变量的状态机流转；
  - 动作收尾与清理：`ExitToIdle` 正常退出 vs 外部打断退出（`OnExit` 彻底关闭 Hitbox）。
- **重点追问**：纯代码时钟相比动画事件解决了什么痛点？多段判定与单招连招窗口有何区别？
- **停止边界**：一份标准近战招式配置与一次异常打断，不展开重箭、空中招式等变体。

### 章节 4：命中检测与攻防裁决一体化（扫掠、去重与受击防御）
- **定位**：攻防对抗的核心碰撞与裁决（原章节 4 与 5 合并，攻防一体）。
- **入口与范围**：
  - 物理查询：`Hitbox.LateUpdate` 中 `SphereCastAll` 体积扫掠（防高速穿模）与 `OverlapSphere`（防贴身漏判）；
  - 去重机制：为什么在挥刀段内维护已命中列表？何时清空？
  - 中枢转发：`Hitbox` $\rightarrow$ `CombatResolver` $\rightarrow$ 防守方 `CharacterBody.ReceiveHit`；
  - **防御状态机即时裁决（核心）**：
    1. 处于 `DodgeState`（无敌帧期间）：完全穿透忽略；
    2. 处于 `DeflectState`（完美弹反窗）：触发弹反！攻击方被弹刀硬直，防守方涨极少架势，播放铁音；
    3. 处于 `DeflectState`（普通格挡期）：免除 HP 扣除，防守方消耗大量架势值；
    4. 处于无防御态（`Idle / Attack`）：肉身受击，扣除 HP，强制切入受击硬直态 `StunState`；
  - 数值沉淀与表现广播：`CombatStats` 结算 HP 与 Posture，通过 `CombatEventBus` 广播事件更新 UI 与音效。
- **重点追问**：为什么说“检测到物理接触不等于扣血”？完美弹反与普通格挡在代码分支上有何根本区别？
- **停止边界**：走通一条从扫掠到四路裁决的完整闭环，不展开所有特殊投射物与危字投技。

### 章节 5：Boss 怎样选择与执行行动（行为树与 HFSM 协同）
- **定位**：AI 决策与动作执行的分离架构。
- **入口与范围**：
  - `BTBrain` 驱动架构：行为树周期评估 vs HFSM 动作长周期执行的分工；
  - 节点评估与黑板：`Node / Selector / ISelectorLock / Blackboard`，评估优先级与招式锁定语义；
  - 候选筛选：`BT_PickActive` $\rightarrow$ `BossMovePicker` 结合距离、冷却与权重筛选招式条目；
  - 动作执行与转化：`BT_ExecuteMove` 推进，通过 `BossAttackBaker` 将配置烘焙为 `AttackConfig` 接入 HFSM；
  - 选讲亮点：识破（`MikiriCounter`）或喝药惩罚（`HealPunish`）的专属行为分支。
- **重点追问**：行为树每帧评估，如何防止 Boss 频繁变招打断当前攻击？AI 出招与玩家出招在 HFSM 中如何统一？
- **停止边界**：走通一次普通主动选招、执行与打断，不通读整棵树的全部叶子节点。

### 章节 6：架势崩解、忍杀、胜负与战斗生命周期
- **定位**：战斗收尾与整场调度。
- **入口与范围**：
  - 架势崩解（Posture Broken）：`CombatStats` 架势打满触发回调，角色进入失衡瘫痪状态；
  - 处决机会与触发：玩家在近距离按下攻击，触发 `FinisherCommand`；
  - 双人演出同步：`DuelDirector` 接管双方，锁定双方动作（`IsFinisherLocked`），同步位置朝向，播放同步处决动画；
  - 胜负判定与重置：命数扣除、胜负判定，通过 `EncounterScope` 区分场内快速重置与场景重载。
- **重点追问**：处决期间如何彻底封锁双方的输入与伤害？重开时哪些静态数据与运行时状态必须复位？
- **停止边界**：走通一次崩解处决与胜负复位，不展开镜头运镜曲线与粒子特效细节。

### 章节 7：全流程串联与高频面试表达复盘
- **定位**：终极复盘与面试实战。
- **核心内容**：
  - 串联全流程：玩家出招 $\rightarrow$ Boss 完美弹反 $\rightarrow$ Boss 连招出招 $\rightarrow$ 玩家闪避与识破 $\rightarrow$ Boss 架势打满 $\rightarrow$ 忍杀处决；
  - 针对简历 5 大技术点逐一整理标准回答模版（痛点、实现原理、取舍权衡、性能考虑）；
  - 真实排错经历复盘（如：高速挥刀穿模排查、处决输入穿透排查）。
