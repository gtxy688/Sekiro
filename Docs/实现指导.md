# 跨模块实现说明

> 本文记录当前源码中的主要职责边界与调用关系，不是未来开发计划。代码、序列化资源和场景共同定义当前实现；不以旧计划的状态描述覆盖它们。

## 玩家控制到状态机

PlayerInputActions / PlayerInput 提供输入。PlayerBrain 将移动作为连续输入送给 CharacterBody；离散动作通过 BrainBase 缓冲后调用 CharacterBody 的命令入口。状态机由顶层父状态和其 SubStateMachine 共同路由命令。

查询地面父状态或切换其子状态时，业务代码使用 CharacterBody 的封装 API，避免把顶层父状态和叶子状态混为一类。

## Boss 决策到攻击状态

BTBrain 更新行为树与 Blackboard。选招逻辑根据 BossMoveTable、距离、冷却与行为上下文选择 BossMoveEntry。BT_ExecuteMove 将招式的动画序列和对应 BossMoveWindow 烘焙为运行时 AttackConfig，再交给 CharacterBody 启动攻击状态。

## 动画时间到命中与表现

AttackStateBase 每次更新读取 AttackAnimClock 的动画秒数。HitStartTime / RecoveryWindowStart / hitPulses 控制近战判定时间；sfxCues 和 arrowCues 控制音效与出箭。攻击时间数据存在 AttackConfig 或 BossMoveTable，不靠 Animation Event 开关近战 Hitbox 或发箭。

Hitbox 通过 SphereCast 与 Overlap 查询目标。ArrowProjectile 执行自身的投射物扫描。两者将命中报告给 CombatManager，由 CombatResolver 调用目标 CharacterBody.ReceiveHit；状态机处理防御、无敌、受击与后续状态。

## 伤害配置与默认值

玩家招式主要读取 AttackConfig。Boss 近战数据由 BossMoveEntry、BossMoveWindow 和 HitPulse 提供；箭矢从对应招式行与 ArrowSpawnCue 解析。覆盖数据优先于招式默认值。AttackCombatResolve 另有按 HitGrade / 是否箭矢选择的代码默认值，因此“无硬编码数值”不是准确描述。

## 表现事件

CombatEventBus 是表现通知入口之一。CombatUIController、AudioManager 与相机相关组件订阅它们需要的事件，并在禁用时取消订阅。不要将 UI 描述成完整 MVC；各 View 的数据绑定与输入由当前组件实现决定。

## 文档与计划

Docs/superpowers/plans 和 specs 保存历史计划快照；其中的 TODO 与实现状态不一定同步。新实现说明必须先对应当前源码，未实现目标要单独标注为计划。
