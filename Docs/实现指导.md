## 1. 总体实现思路

### 1.1 一句话核心

**玩家和 Boss 共用同一套「身体 + 状态机」，区别只在"大脑"层**：
- 玩家的"大脑"是键盘鼠标（`PlayerBrain`）
- Boss 的"大脑"是行为树（`BTBrain`）
- 两者都说同一种语言（Command），驱动同一辆车（`CharacterBody` + `StateMachine`）

### 1.2 三股数据流（全项目就这三条线）

```
① 指令流：   大脑(输入/AI) → Command → StateMachine → 状态切换
② 受击流：   武器 Hitbox 扫到 Hurtbox → CombatManager → ReceiveHit → 状态机裁决 → 扣血/拦截
③ 表现流：   战斗逻辑 → CombatEventBus(事件) → UI/音效/相机/特效（纯订阅，不轮询）
```

### 1.3 硬性红线（写代码时严格遵守）

1. HFSM 顶层只装父状态（Grounded/Air/Stunned），叶子状态永远在父状态的 SubStateMachine 里。
2. 禁止直接判顶层状态类型（`CurrentState is DodgeState` 永远 false），查状态走层级路由。
3. 命中判定不用 OnTrigger，用 SphereCast（上一帧→当前帧扫）。
4. 伤害数值只放 `AttackConfig`（SO），角色属性只放 `CharacterConfig`（SO），不硬编码。
5. Hit 结算必须走 `CombatManager` 中间层，Hitbox 不直接调 `ReceiveHit`。
6. 环境/物理强制切换（受击、落地）不走 Command，直接 `ChangeState`。
7. 表现层（UI/音效/相机/特效）只订阅 `CombatEventBus`，不做每帧轮询。

## 3. 分模块实现思路

### 基础层

**M1 HFSM 受击路由（✅ 已实现）**
思路已定：`ReceiveHit` 打包 HitData → 逐层问 `OnHitReceived`（父拦截 → 子处理）→ 没人拦就扣血 + 强切 StunnedState。不动。

**M2 战斗属性（✅ 已实现）**
思路已定：数值全走 SO。`CharacterBody` 持有 Config，运行时初始化 HP/架势/葫芦/复活。不动。

**M5 行为树框架（🔶 补两块）**
- **黑板（Blackboard）**：一个键值字典挂在树根，所有节点共享（存"目标、攻击距离、当前连段第几刀、招式冷却"等）。
- **Running 记忆**：现在 Sequence/Selector 每帧从头遍历。改成"记住当前跑到第几个子节点"，子节点返回 Running 时下一帧接着跑，不重头再来。
- 这是纯框架层，做完让 M7 的 Boss AI 好用。

### 战斗层

**M3 命中判定（✅ 已实现）**
思路已定：武器上一帧→当前帧 SphereCast 扫，扫到 Hurtbox 报 CombatManager 结算，扫到对方 Hitbox 报拼刀。不动。

**M4 弹反/格挡（⬜ 核心，全项目手感所在）**
思路（对应策划案"方案 B"）：
1. **按下右键** → 进 DeflectState，立刻举刀，同时开启一个 **0.3s 弹反窗口**。
2. **窗口内挨打** → 完美弹反：涨 Boss 架势 + 双方短暂硬直（"弹开"）+ 清脆"叮"声 + 大火花；自己涨少量架势但**永不因此崩解**。
3. **窗口过了仍按着** → 格挡：不扣血，只涨自己架势 + 沉闷"笃"声 + 小火花。
4. **松手** → 回待机；短按（<0.15s）松手播一个**收刀/弹反专属动画**——与普通格挡的举刀姿态是**两段不同动画**（具体用哪段后续定，不一定是"甩刀"）。
5. **抖刀惩罚**：0.5s 内连点右键 ≥3 次 → 弹反窗口 ×0.75（下限 0.1s）；停止点击 0.5s 后窗口恢复到 0.3s。
6. **危字攻击不可格挡/弹反**：DeflectState 看到 `isPerilous` 直接放行（交给垫步/跳踩/挨打处理）。

**M9 架势系统（🔶 补回复 + 崩解表现）**
思路：
1. **玩家回复**：停止受击 2s 后每秒回 20；**按住格挡 2s 后**回复 ×5（格挡回架势快）。
2. **Boss 回复**：`回复速度 = 基础 × (1 − 当前架势 / 最大架势)`——架势越低回得越快，越高越慢（"反函数"手感）。**基础 ≈ 5/s**（空架势约 5/s，满架势回 0）。
3. **玩家架势崩解**：播**击飞倒地**专用动画，倒地后架势清空，**不被 Boss 处决**。
4. **Boss 架势崩解**：进入**处决窗口 5s**，UI 红点高亮，发 `OnPostureBroken`。
5. 现有 `AccumulatePosture` 已能累积+触发崩解，要补的是"非线性回复"和"崩解后的表现状态"。

**M10 处决/忍杀（⬜）**
思路：
1. Boss 需要新增一个**"剩余命数"字段**（一阶段 2 条命，对应左上角 2 红点）。
2. Boss 架势崩解 → Boss 进"崩解硬直"（可被处决，5s 窗口倒计时）。
3. 玩家**走近 + 按攻击键** → 播处决动画 → 动画命中帧调"清一条命"（命数 −1 + 架势清零）。
4. 命数没清完 → 回战斗继续压制；**清完 2 条 → 胜利**。

**M17 危字攻击（🔶 突刺✅，横扫⬜）**
思路：
- **突刺（已实现）**：Boss 突刺（危字标记 Thrust）→ 玩家垫步 → 识破踩刀 → 涨 Boss 架势。
- **横扫（待做）**：Boss 横扫（危字标记 Sweep）→ 玩家**跳跃踩踏**反制 → 涨 Boss 架势。思路：新增一个"跳踩"判定（玩家空中下落踩中横扫 → 打断 Boss + 涨架势），或复用 AirIdleState 加一个 SweepCounter 子状态。
- "危"字 UI：Boss 出危字招式时发 `OnPerilousAttack` → 屏幕弹"危"。

### 控制层

**M6 输入（✅ 已实现）**
思路已定：WASD 移动 + 鼠标左键攻击 + 右键防御 + Shift 垫步 + 空格跳 + E 葫芦 + 中键锁定。离散按键走 0.2s 缓冲池。不动。

**M11 锁定（⬜）**
思路：
1. **LockOnManager**：中键切换锁定/解锁。单 Boss，锁定目标就是 Boss（不做切目标）。
2. **锁定中**：MoveState **面向 Boss**（覆盖摇杆转身），移动相对 Boss 绕圈；**解锁**：恢复现在的"相机相对"移动（已有 `InputToWorldDir`）。
3. **锁定点 UI**：白点挂 Boss 身上，架势崩解变红点。
4. 锁定状态同时通知相机（M12 切换虚拟相机优先级）。

### 表现层

**M12 相机（⬜，用 Cinemachine，不用自写的 OrbitCamera）**
思路：
1. **自由视角**：`CinemachineFreeLook`，Follow 玩家、LookAt 胸口高度的 AimTarget，鼠标 X/Y 旋转，滚轮缩放（一个小脚本改三个 rig 的 Radius）。
2. **锁定视角**：一个 `CinemachineVirtualCamera`，Follow 玩家、LookAt Boss，**Priority 高于 FreeLook**；锁定时拉高它，Cinemachine 自动 blending 切过去。
3. **震屏**：订阅 `OnCameraShake` → Cinemachine Impulse。
4. 防穿墙：挂 `CinemachineCollider`。

**M13 UI（🔶 框架已建）**
思路已定：MVC。`CombatUIController` 订阅 `CombatEventBus`，按 `CharacterBody` 区分玩家/Boss，路由到各 View。布局按策划案（顶部 Boss 架势、底部玩家架势、左上血条+红点、左下回生、右下葫芦、锁定点、"危"字）。DoTween 做架势条高亮/红点脉动。框架已有，接场景即可。

**M14 复活（⬜）**
思路：
1. **死亡**：有复活次数 → 弹"回生"提示 → 玩家按**攻击键（左键/RT）**确认回生（**回满血 + 架势清零 + 短暂无敌帧**），Boss **不重置**，接着打。
2. **无复活** → 真死 → 死亡动画 → 弹出**死亡 UI 界面** → 重新加载场景（具体交互我定，倾向：死亡 UI 出现后按键重载）。
3. 数据层 `Revive()` 已就绪，要补的是"回生动画 + 无敌帧 + 确认输入"。

**M15 音效（🔶 框架已建）**
思路已定：`AudioManager` 订阅事件播音频。格挡 / 弹反从 `Resources/Sounds` 装池随机（不连抽）；玩家 / Boss 受击各一条 Inspector；处决、危字等仍 Inspector。

**M16 葫芦（⬜）**
思路：
1. HealCommand → 进**喝药状态**（播喝药动画，期间不可移动/攻击）。
2. 喝药**可被打断**（受击打断，血没回成）。
3. 动画完成帧 → `UseGourd()` 回满血。
4. 现在 GroundedState 里是"即喝即回"，要改成"进喝药状态 + 动画完成才回血"。

### AI 层

**M7 弦一郎 AI（⬜）**
思路（对应策划案三层 + 行为树）：
1. **主动进攻层**：按距离分段选招（远→射箭/飞渡符舟/接近；中→近战连段/肘击；近→贴身连段）。
2. **交锋计划层**：被玩家完美弹反"弹开"后变招（换一套打法，不让玩家摸到规律）。
3. **防御/招架层**：玩家连续攻击时 Boss 防御，时机好就**完美弹反玩家**（把玩家弹开小硬直）。
4. **招式冷却**：每个招式有冷却，用黑板存，防止连续放同一招。
5. **射箭**：投射物（见 4.6），从弓弦位置生成朝玩家飞。
6. 参考 `references/sekiro-genichiro-ai.md`，但**该文档不完整**，遇到缺失的招式逻辑/数值会停下问你，不自己补。

### 集成层

**M8 攻击接线（⬜ 硬伤，第一步先做）**
思路：让攻击真正出伤害。AttackState 在"攻击判定帧"内开 Hitbox、结束帧关。两种做法：
- **A. 代码驱动（推荐）**：给 `AttackConfig` 加"判定开始/结束时间"两个字段，AttackState 按 stateTimer 开关判定。数值集中 SO，不用逐段动画手动配事件，改起来方便。
- **B. 动画事件**：每段攻击动画 Clip 的关键帧配 Enable/Disable 事件。精确但每段都要手动配、易漏。
- **已确认用 A（代码驱动）**：给 `AttackConfig` 加"判定开始/结束时间"字段，AttackState 按计时开关判定。

### 跨模块

**打击感（hitstop + 火花）**
- **hitstop（停顿）**：命中/弹反瞬间让双方短暂"卡"一下（命中 ~0.05s、完美弹反 ~0.1s），营造打击重量感。
- **火花**：已有 FXManager，完美弹反大火花、格挡小火花。

**场景装配（⬜，纯 Editor 操作，无代码）**

## 4. 关键机制展开（重点核对思路）

### 4.1 弹反"短按 / 长按"如何区分
- 核心不是"按下多久判定弹反"，而是**"按下即开 0.3s 弹反窗口"**：窗口内挨打=弹反，窗口后按住=格挡。
- "短按 <0.15s"只影响**松手后的表现**：短按播弹反专属动画（与格挡举刀是两段不同动画），长按直接收刀回待机。
- 抖刀惩罚独立计时：统计 0.5s 内连点次数，≥3 次就缩小窗口。

### 4.2 5 段连招派生
- 现有 `AttackState` 已用 `AttackConfig.NextCombo` 链式派生（Attack1→2→3→4→5）。
- 连招窗口内再按攻击键 → 切下一段；错过窗口 → 回待机。
- M8 只需补上每段攻击的"开/关 Hitbox"，连招链本身已通。

### 4.3 非线性架势回复
- 玩家：线性（固定 20/s，格挡 ×5），靠"延迟 2s + 倍率"体现手感。
- Boss：反函数（架势越低回越快），越打越接近崩解时 Boss 越难回——这正是只狼"压制 Boss"的核心手感来源。

### 4.4 Boss 三层 AI 如何落到行为树
- 顶层是一个 Selector，优先级从高到低：**防御招架 > 交锋变招 > 主动进攻**。
- 每层内部用 Sequence（条件 + 动作），距离/架势比/连续防御次数等状态放黑板，节点读黑板决策。
- "被弹开变招" = 订阅弹反事件 → 置黑板标志 → 树下次 Evaluate 走变招分支。

### 4.5 共用状态的动画名问题（重要）
- 状态代码里动画名是硬编码逻辑名（Idle/Walk/Hurt_Ground/Jump/Fall/Dodge/Mikiri）。
- 玩家和 Boss 用同一套状态，所以**两个 Animator 用相同状态名、绑各自的动画 Clip** 即可，代码不用改。
- **已确认**：用"同名状态名、各绑各的动画"方案，动画最终都由状态机统一播放，代码不改。

### 4.6 射箭（投射物）
- 箭做成 prefab：挂一个"匀速直线飞行 + 上一帧→当前帧 SphereCast 扫玩家 Hurtbox"的小脚本。
- 弓动画"撒手"帧用动画事件生成箭，方向锁定"开火瞬间指向玩家胸口"，**不追踪**（只狼的箭可躲）。
- 命中 → 走 CombatManager 结算；箭可被垫步无敌帧躲过。

### 4.7 hitstop 实现
- 命中/弹反瞬间，让双方动画+位移短暂冻结（命中 ~0.05s、完美弹反 ~0.1s），营造"打中了"的重量感。
- 只冻"战斗时间"，UI/相机不冻；实现上用小段时间缩放或协程暂停双方 Animator。

## 6. 可能缺少的模块（我主动提醒）

1. **战斗流程管理器（缺）**：目前没有"开战 → 战斗中 → Boss 死/玩家死 → 重开"的流程负责人（`Main.cs` 是空的）。必须加一个 `CombatFlow` 管理器：**玩家进入触发范围 → 开战（弹 Boss 血条）→ 胜负判定 → 玩家真死 → 死亡 UI + 重新加载场景**。

3. **hitstop 归属（缺）**：打击感里的"停顿"没模块认领，建议并入 M15（音效）旁建一个"打击感/TimeScale"小模块，或并入 CombatManager。

5. **Boss 受击/格挡动画**：已确认"同名状态名"方案，共用状态会自动播 Boss 自己的受击/格挡动画（动画资源后续接）。
